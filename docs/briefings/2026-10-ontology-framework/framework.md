## 0. 摘要

- **定性**：把企业关于"什么算什么"的共识，变成可执行、可追溯、可演化的资产。数据中台解决"数在哪"，语义中台解决"数是什么、凭什么信、谁说了算"。
- **三个判断**：
  - 唯一真相是伪命题。多义可以，歧义不行。
  - 口径之争是承认之争，所以治理流程本身就是本体的一部分。
  - 语义是企业里半衰期最长的数据资产，必须独立于引擎和 BI，而且可以迁移。
- **AI 带来的变化**：提议语义几乎免费，确认语义依然昂贵。产品重心应该从建模工具转向裁决与验证系统。
- **切入点**：选一个高压领域，做"可信问数 + 口径差异解释"。北极星指标是可信回答率。

## 1. 定性：语义中台到底在管什么

### 1.1 企业数据里的三层存在

| 层 | 内容 | 例子 |
| --- | --- | --- |
| 实在层 | 原始事实（brute facts） | 客户付了款，货出了库 |
| 制度层 | 制度性事实，靠组织集体承认才成立 | 这笔款算不算收入？这个用户算不算活跃？这家店还算不算可比门店？ |
| 表征层 | 描述前两层的符号 | 表、字段、日志、API、报表、文档 |

制度层的事实在物理世界里找不到。它们之所以存在，是因为组织认可了一条规则，也就是 Searle 说的构成性规则：**X 在情境 C 中算作 Y**。

数据中台的主战场在表征层：汇数、建模、出宽表。企业里真正吵架的地方却在制度层。"口径"说到底就是制度性事实的构成规则。

### 1.2 产品定义

**把企业关于"什么算什么"的共识，变成可执行、可追溯、可演化的资产。**

它要同时扮演三个角色：

- **登记处**：登记业务世界里有什么，每样东西怎么定义。
- **仲裁庭**：口径有分歧时由它裁决，并把决定留档。
- **编译器**：把批准过的意义编译成人、系统和 AI 都能执行的计算与动作。

### 1.3 三个推论

1. **"唯一真相"是伪命题。** 同一个 X 在不同的 C 里，可以正当地算作不同的 Y：财务口径、管理口径、考核口径、监管口径各有道理。产品不该承诺"只有一个数"，而要承诺"每个数都说得清、对得上"。原则是：**多义可以，歧义不行。**
2. **口径之争本质是承认之争，也是权力之争。** 考核口径直接决定奖金。本体的经典定义是"对共享概念化的显式规约"，重点在"共享"。所以提议、审议、批准、生效、废止这套流程不是附加功能，它就是本体的一部分。没人批准过的定义只是个人观点。
3. **表征层常变，制度层稳定。** 国产化替代、上云、并购、换 ERP，物理层几年就要翻一遍，"什么算收入"却能稳定很多年。语义是企业里半衰期最长的数据资产，必须独立于任何引擎和 BI，并且可以迁移。

## 2. 本体论八问与产品能力

### 2.1 对照表

| 本体论问题 | 企业里的症状 | 产品能力 |
| --- | --- | --- |
| **范畴**：存在哪几类东西 | 客户、订单、指标、事件统统叫"表" | 类型化元模型：实体类型 / 角色 / 关系体 / 事件 / 状态阶段 / 度量 / 规则 |
| **同一性**：凭什么算同一个 | 一客多档；门店装修、搬迁、扩面积后还算不算"同店"（忒修斯之船） | 每个实体类型声明同一性准则；实体解析；跨时间同一性规则 |
| **构成**：X 在 C 中算作 Y | 口径之争 | 口径 = 情境化的可执行定义，带适用范围、负责人、生效期 |
| **部分与整体** | 汇总对不上；组织架构调整后同比怎么算 | 层级、可加性、勾稽校验；明确按旧架构（as-was）还是新架构（as-is）看数 |
| **时间与变化** | 定义改了，历史数要不要重述 | 双时态（有效时间 + 记录时间）、语义版本、追溯规则 |
| **指称**：符号指向什么 | 同名异义（"收入"），同义异名（GMV / 成交额 / 流水） | 符号、概念、所指三分；绑定与血缘 |
| **应然**：谁能看、能做什么 | 权限挂在表上，换张表就失控 | 策略挂在概念上，自动传播到所有物理绑定；顺带解决分类分级 |
| **行动**：能对对象做什么 | Agent 只能查，或者乱做 | 动作语义：前置条件、效果、权限、审批 |

### 2.2 范畴决定计算行为

这张表里最值钱的是一条：**范畴决定计算行为。** 脏数字大多来自范畴错误：

- **把角色当类型。** "客户"不是一种东西，而是当事人在交易关系里扮演的角色，同一家公司可以既是客户又是供应商。把角色建成实体表，主数据就会打架。
- **把存量当流量。** 余额、库存是时点状态，跨时间不能求和；销售额是区间流量，可以累加。
- **把强度量当广延量。** 转化率、单价不能相加，平均值也不能再求平均。
- **一个词背后有三种对象。** "订单"同时是一次下单事件、一个有生命周期的买卖承诺（关系体），以及一张单据（信息实体）。不区分清楚，"订单数"就会有三种算法。
- **不声明关系基数。** 一对多关系没标出来，就会掉进扇形陷阱，重复计数。

用户只要选对了范畴，平台就知道该怎么处理同一性、时间、聚合和权限。本体论在这里不是学术装饰：**它是防止 AI 把订单行金额重复求和的那道护栏。**

## 3. 核心元模型

### 3.1 四个问题

| 问题 | 对象 | 要点 |
| --- | --- | --- |
| **说什么**（语言） | 术语 | 同义词、简称、行业黑话、多语言。帮人和 LLM 确认一个词指的是什么 |
| **是什么**（本体） | 概念、关系、情境 | 概念有范畴、同一性准则和负责人；关系带基数；情境 = 限界上下文 + 用途 + 有效期 |
| **怎么算、怎么做**（操作化） | 口径、策略、动作 | 口径是概念在某个情境下的可执行形式：度量、聚合、粒度、过滤、时间语义、可加性、单位 |
| **凭什么信**（证据与治理） | 绑定、证据、决议、观测值 | 绑定连接物理资产；证据包括样本、血缘、对账结果、制度原文；决议记录谁在什么范围批准了哪个版本；观测值是带"出生证明"的具体数字 |

### 3.2 两条架构原则

1. **概念、口径、数值分开。** "收入"（概念）、"管理口径收入 v3"（算法）、"Q3 收入 12.3 亿"（观测值）是三种不同的对象。多数指标平台把它们揉成一个"指标"，所以回答不了"这两个数为什么不一样"。
2. **事实不可变，解释可以改版本。** 事实层坚持"发生了就是发生了"，只追加，不改写。口径层承认解释是人定的，可以修订，历史数据可以按新口径重算。

### 3.3 语义生命周期

```text
发现 → 提议 → 审议 → 批准 → 绑定 → 发布 → 服务 → 观测 → 演化 / 废止
  ↑                                                        │
  └──────────── 质疑、缺口、失败、变更影响 ←───────────────┘
```

每次状态变化都要回答四个问题：谁做的，依据什么证据，适用于什么情境，从什么时候起生效。

### 3.4 市场空位

- 指标平台只管"怎么算"，数据目录只管"有什么"，知识图谱偏"是什么"。
- 治理产品有流程，但不在出数的链路上；指标产品在出数的链路上，却记录不了共识和证据。

谁能把"凭什么信"做成核心对象，并让批准过的定义直接编译成数字，谁就占住了这个位置。

## 4. AI 改变了这个品类的成本结构

### 4.1 过去为什么做不成

过去语义层失败有三个原因：建模贵（要请顾问，一做几个月），维护跟不上（定义很快过时），业务方不参与。Palantir 证明了本体能撑起 AI 进入业务运营，但它的本体靠驻场工程师一个客户一个客户搭出来。

### 4.2 成本结构的变化

LLM 让"提议语义"几乎零成本：schema、SQL 日志、BI 报表、制度文档、会议纪要都能抽出候选概念和映射。"确认语义"的成本却没降，谁说了算、和财务对不对得上，仍然要人来定。提议越多，确认反而越贵。

### 4.3 设计推论

- **重心从建模工具转向裁决与验证系统。** AI 提议，人来裁决。最关键、也最常被忽视的用户是领域负责人，产品成败取决于他们愿不愿意花十分钟批一个定义。他们的待办按"影响面 × 置信度"排序，证据就放在旁边。
- **LLM 负责理解，编译器负责正确。** 问数链路是：问题 → 识别概念 → 选定情境 → 编译口径 → 确定性执行 → 带出生证明的答案。涉及受管控的指标时，不让 LLM 直接对原始表写 SQL。
- **Agent 是新的一等用户。** 它需要机器可读的情境化语义（通过 MCP 等接口提供）、遇到歧义时的澄清机制、置信度和拒答能力，以后还需要带护栏的动作语义。Agent 会放大范畴错误：人看到怪数字会起疑，Agent 却会照样写进报告。
- **信任要分级。** 语义成熟度依次是：AI 候选 → 草案 → 领域内批准 → 企业认证。董事会材料只能用认证级语义，探索分析可以放宽。

## 5. 用户与角色

| 角色 | 关心什么 | 产品给什么 |
| --- | --- | --- |
| CFO / CDO（买单方） | 会上少吵架，AI 能用，合规过得去 | 口径争议看板、可信回答率、认证口径清单 |
| 领域负责人（决定成败的用户） | 别让我花太多时间，但要我说了算 | 按影响排序的裁决待办、证据就近、批量确认 |
| 分析师 / 数据工程师（作者） | 写得快、测得了、改得动 | 口径起草、测试、差异桥、影响面 |
| 治理团队（看护者） | 标准一致、变更可控 | 近似重复拦截、变更通知、语义健康度 |
| 业务用户（消费者） | 一个能信的答案，看得懂来龙去脉 | 带出生证明的答案、其他口径提示、一键质疑 |
| AI Agent（机器用户） | 机器可读的语义、明确的边界 | MCP 工具、澄清协议、置信度、拒答、动作护栏 |

## 6. 切入点、关键功能与飞轮

### 6.1 切入点

选一个高压领域，比如经营分析会上的三五十个核心指标，做"可信问数 + 口径差异解释"。这里的痛点高管当场就能看到，范围又可控，几周就能见效。

### 6.2 四个关键功能

1. **口径差异桥。** 先结构化对比两个口径，再把差异逐项量化成瀑布图，例如："考核口径比财务口径高 3.2%：计入 7 天内取消的订单 +2.1%，含税 +1.4%，剔除内部账户 −0.3%。"这是把概念和口径分开之后才做得出来的能力，别人很难补上。
2. **带出生证明的答案。** 每个数都附上口径版本、批准人、数据截止时间和计算路径，并显示其他口径下的值。答案旁有"一键质疑"，质疑直接进入治理流程。
3. **变更影响面。** 定义从 v3 升到 v4 时，自动列出受影响的报表、Agent 和下游系统，判断历史数据要不要重算，并通知相关的人。
4. **拦截近似重复的口径。** 新指标如果只比已有指标多一个过滤条件，系统要求合并，或者写明区别，从源头控制指标数量失控。

### 6.3 飞轮

```text
有人提问 → 答不了 / 答错 / 有歧义 → 自动记为语义缺口 → AI 起草定义
    ↑                                                        │
    └── 覆盖率、准确率上升 ← 负责人批准 ←─────────────────────┘
```

**治理应该是使用的副产品，而不是使用的前提。** 治理待办来自真实的问题，不需要先去盘点几万张表。

### 6.4 扩张路径

分析语义 → 实体与同一性（轻量主数据）→ 合规语义（分类分级、监管报送映射，比如 EAST / 1104）→ 行动语义（Agent 可执行的操作）→ 跨组织的语义互认（可信数据空间）。

## 7. 怎么衡量

| 类型 | 指标 | 说明 |
| --- | --- | --- |
| 北极星 | 可信回答率 | 人和 Agent 提的业务问题里，用已批准语义回答、且没有被质疑或纠正的比例 |
| 覆盖 | 按需求加权的覆盖率 | 被问到的概念里有多少已经批准。编目了多少张表不重要 |
| 共识 | 口径争议的解决时长 | 从提出质疑到批准决议的时间 |
| 正确性 | 标准问题集准确率 | 持续做回归测试 |
| 反指标 | 概念总数、指标总数 | 这两个数上涨，往往是本体在膨胀，不代表价值在增长 |

## 8. 明确不做什么

- **不做本体编辑器。** 企业里没有本体工程师。本体论是产品经理想清楚问题的工具，不该变成用户界面上的术语。界面上应该问"你们怎么判断两个客户是同一个"，而不是让人填"同一性准则"。
- **不做自上而下的大一统模型。** 遵循"最小本体承诺"：一个很薄的核心（当事人、产品、时间、地点、货币、事件），加上各领域自治，再加显式映射。只为真实问题建模。
- **不教条地套用 RDF/OWL。** 它假设"没记录的不等于不存在"（开放世界），适合整合知识；指标计算却要求"没记录就是没有"（封闭世界），还要做约束校验。内部用实用的类型化模型，对外支持 OWL/SHACL、OSI、dbt 等格式的导入导出。
- **不做没有语义支撑的 NL2SQL。** 它的准确率有上限，而且给 CEO 报错一次数，信任就没了。
- **不把语义锁进某个 BI 或引擎。** Snowflake、Databricks、微软都已经把语义层或本体内置进平台，OSI 也在推动开放交换，单纯的"指标层"正在变成平台自带的功能。护城河在别处：
  - 不绑定任何引擎；
  - 共识和证据积累成的企业记忆，越用越难迁走；
  - 让业务专家用得顺手；
  - 为 Agent 提供可信保障。
- **少讲"中台"。** 很多客户一听"中台"就想到"投入重、见效慢"。更好的说法是"让人和 AI 用同一套可信口径"，并且按领域、按周交付价值。

## 9. 分阶段路线（示意）

| 阶段 | 目标 | 关键范围 | 退出标准 |
| --- | --- | --- | --- |
| 0 → 1 | 一个领域做透 | 三五十个核心指标；概念、口径、情境三分；批准流程；可信问数、差异桥、出生证明；MCP | 该领域经营会上不再为口径争吵；可信回答率稳定达标 |
| 1 → 10 | 多领域联邦 | 领域自治加显式映射；实体同一性；变更影响与历史重述；标准问题集回归；语义级权限传播 | 新领域接入周期和争议解决时长持续下降 |
| 10 → 100 | 从"看数"到"做事" | 动作语义与护栏；行业模板；跨组织的语义互认 | Agent 能在受控范围内执行业务动作 |

## 附录：本体论术语速查

| 术语 | 含义 | 在产品里的落点 |
| --- | --- | --- |
| 原始事实 / 制度性事实 | 物理上发生的事 / 因集体承认才成立的事 | 事实层与口径层分开 |
| 构成性规则 | Searle 的公式：X 在情境 C 中算作 Y | 口径 = 绑定情境的定义 |
| 范畴 | 存在物的基本种类 | 类型化元模型 |
| 同一性准则 | 判定"是同一个"的条件 | 实体解析、跨时间同一性 |
| 刚性 / 反刚性 | 一个类型是否终身、必然地适用于它的实例（"人"是刚性的，"客户"是反刚性的） | 区分类型、角色和阶段 |
| 关系体 | 让关系成立的独立对象，比如合同、订单、雇佣 | 有生命周期的业务对象 |
| 广延量 / 强度量 | 可以按部分相加的量 / 不能相加的量 | 可加性约束 |
| 存量 / 流量 | 时点状态 / 区间累计 | 半可加性 |
| 双时态 | 有效时间 + 记录时间 | 时点查询（as-of）与历史重述 |
| 最小本体承诺 | 只对必要的东西承认其存在 | 按需求生长，防止本体膨胀 |
| 开放世界 / 封闭世界假设 | 没记录不等于假 / 没记录就是假 | 知识整合用前者，计算用后者 |
| 语义三角 | 符号、概念、所指 | 术语、概念、绑定三分 |
