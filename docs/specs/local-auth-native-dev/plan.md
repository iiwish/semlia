# 正式本地登录与本机开发

Status: Confirmed
Task: LAD-T001
需求依据：用户要求仅保留正常运行模式、本机直接运行应用并连接 OrbStack PostgreSQL、清理旧应用镜像，并选择新增正式账号密码登录。

本计划以一个合并任务交付，内部按认证、前端收敛、本机启动顺序执行。批准本计划后生成同范围执行包和前像，再进入实现；不自动执行外部 AI 接入任务，不改变 SP-T001 至 SP-T007 历史验收结论。

## 产品边界

- 前端只有正常的登录、会话、工作区和权限路径。删除运行时 fixture 开关、假身份切换和仅用于原型的业务分支，不只是把开关默认关闭。
- 自动化测试可以使用测试夹具及隔离身份供应商，但不得向正常应用注入伪造身份、增加生产可启用的测试后门。
- 默认正式登录方式为本地账号密码。账号名采用不区分大小写的唯一登录标识，支持字母、数字、点、下划线、短横线组成的 1 至 64 字符名称（如 `admin`）及邮箱格式；邮箱格式不代表邮箱已验证，不自动关联同邮箱 OIDC 账户或授权现有工作区。
- 保留既有 OIDC 作为可选认证提供方，两者复用同一正常应用、会话及授权体系，不保留第二套前端运行模式。
- 提供登录、退出、本人修改密码，以及管理端受权限控制的本地成员创建/停用。首次管理员与遗失密码恢复使用显式本机管理命令，不开放匿名注册或无验证的找回密码接口。
- 本轮不建设邮件发送、邮箱自助重置、MFA 或社交登录。管理员不获得查看任何人明文密码的能力。

## 认证设计

1. 复用 `user_accounts`、`workspace_memberships`、principal、角色授权和不透明会话；本地密码凭据独立存储。不通过伪造 OIDC issuer/subject 实现本地登录。
2. 使用已锁定 `golang.org/x/crypto` 的 Argon2id，随机盐及带版本参数的哈希记录；最低参数 m=19 MiB、t=2、p=1，解析时限制参数和输入大小，避免畸形记录造成资源耗尽。不存明文或可解密密码。
3. 无 MFA 的密码至少 6 字符，允许空格和长口令，不强制大小写符号组合，不静默截断。限定最大长度及请求体大小，拒绝常见弱口令。密码不可写入 CLI 参数、URL、日志、仓库或验收证据。
4. 登录使用统一失败提示；不存在、停用或错误密码均不能暴露账户是否存在。进入昂贵哈希前实施限流，同时限制并发哈希数量；账户及来源限流支持跨请求/进程一致性，不信任任意转发 IP 头，不采用可被攻击者触发的永久封号。
5. 沿用 HttpOnly、SameSite cookie、CSRF 和明确 Origin 白名单。新增登录接口也有登录 CSRF 防护。非本机 HTTP 场景必须 HTTPS；不能为了开发全局关闭安全 cookie、来源或会话检查。
6. 密码修改/管理员恢复与凭据版本及会话撤销同事务提交；并发旧密码登录不能在撤销后补发有效会话。停用、成员撤销、最后管理员保护沿用既有授权语义。
7. 新增迁移暂定 000029，实施前确认尾号未占用；不修改已发布迁移字节。有本地凭据时禁止有损降级。
8. 本地管理员命令通过终端隐藏输入或受控 stdin 收取密码；初始化具有幂等和并发保护。已有工作区的管理员绑定须明确目标，不静默替换旧 principal、重置角色或接管 OIDC 账户。

密码方案参考 [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)；登录失败、口令策略及节流参考 [OWASP Authentication](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)。

## 本机开发与切换

- `make dev` 面向本机 Go server、worker 和 Vite 热更新，不构建应用 Docker 镜像。保留明确命名的容器发布/隔离验收入口，容器化不是日常开发前置条件。
- 数据库继续使用现有 OrbStack PostgreSQL。监听仅限 loopback，Vite 代理 API；端口冲突必须明确报错或选择并记录新端口，不能连接错误项目。
- 启动器核验 PID、进程身份和归属，失败时清理本轮进程，重复启动不重复运行 worker；停止开发服务不停止 PostgreSQL、不删除数据卷。
- 切换前核对当前 schema、数据库和容器归属，备份数据库、配置及工件/内容卷，保护备份权限，并在独立库验证恢复及迁移。失败不自动覆盖原库恢复，不删除唯一备份。
- 保留现有数据库数据、模型配置、应用加密密钥和模型凭据。凭据仅保存在权限受限的本机配置中，不输出到日志或提交到 Git；不自动调用模型。
- 构建及测试通过后，停止本项目旧 server/worker，执行已验证迁移并启动本机应用。记录旧镜像的精确 ID 和引用；确认新服务可用后才删除不再被使用的 Semlia 应用容器/镜像。
- 不执行 Docker 全局 prune，不删除 PostgreSQL 镜像、数据卷、其他项目镜像或仍被引用的镜像。不将本机切换扩展为远程部署。

## 文件与范围

认证实现限制在 `internal/{domain,application}/identity/`、`internal/adapters/postgres/identity*.go`、`internal/platform/http/{identity*,handler*,catalog*}.go` 中的认证路由及注册、`internal/platform/config/`、`cmd/semlia/` 的身份命令/启动接线及对应测试。

数据及公共契约范围为新增 000029 迁移、`db/queries/identity.sql`、`db/sqlc.yaml`、SQLC 生成物、`api/openapi/semlia.v1.yaml`、对应 Go/TypeScript 生成物、SDK 会话接口与契约测试。不重构其他领域服务。

前端范围为 `web/src/` 中 App/session/identity/成员管理入口、localUAT 删除、运行时 fixture 参数及其专属原型分支移除、对应测试；不重新设计正式业务页面。测试假数据迁入测试专属模块。两尺寸浏览器测试改走真实密码登录和分离账号。

启动与验证范围为 `Makefile`、`scripts/dev/`、`compose*.yaml`、开发构建参数、`web/vite.config.ts`、相关 package scripts、现有验收测试启动器、`docs/operations/local-development.md`、本任务文档与证据。已有依赖仅允许将实际使用的 x/crypto 从 indirect 改为 direct，不扩展版本升级。

执行前据引用检索生成精确 allowed-files 清单并备份当前脏工作区前像。范围外的业务改动、依赖升级或数据清理须另行确认；不以删除测试获得通过。
