## T002 实测输入

首轮 schema 32 的三个正例均未产生可解析输出，负向权限与澄清正常。schema 33 的总量与地区问题已获得真实模型计划；执行被专用来源角色缺少日志隐私设置所拒绝，验收脚本须补专用角色设置而不是放宽适配器。月度问题仍被 schema 门禁拒绝；老客问题在 8192 输出预算下明确触发截断，二者分别诊断，不混为同一根因。

安全元数据确认所用端点主机为 `api.deepseek.com`，模型 `deepseek-flash`。[供应商官方协议](https://api-docs.deepseek.com/api/create-chat-completion/)及[推理模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)说明其默认开启高推理强度。Ask 采用不超过配置且最高 16384 的独立输出预算，保留现有超时和严格结束状态/schema 门禁，不改供应商或默认推理模式。各轮验证有明确修复依据、有限次数并保留全部失败；已成功的模型计划通过新执行 key 复验数据库配置，不为同一结果反复调用模型。

修复边界包括 `tests/smoke/local_stack_test.go` 和专用隔离回归测试。每个嵌套 Docker/Compose 调用及失败恢复都必须使用同一经验证的本地端点、私有 Docker 配置、项目、环境文件和显式 Compose 文件；缺少隔离身份时拒绝执行，不回退到普通开发环境。完整 RED/GREEN、独立复核及真实 smoke 成功之前，T004 不通过。
