# 收敛版 1.0 技术计划

状态：Confirmed。用户于 2026-09-26 明确批准具体技术计划并要求继续完成。产品范围以 `spec.md` 为准。本计划不构成已经完成的发布证据。

## 技术决策

1. 复用 Go 模块化单体、PostgreSQL、现有 React 桌面应用、生成契约和正常 server/worker，不另建演示产品或替代 API。
2. 在现有 Semlia OrbStack PostgreSQL 上使用专属应用库与合成来源库，保留所有既有数据库、账号、配置及内容。所有新建资源记录归属；仅清理本任务创建且无使用者的临时资源。
3. 复用已有订单和客户案例、演示生命周期工具与数据库测试设施；生成固定数据及独立参考 SQL。初始化必须经过正式身份、来源、知识、验证、审核和发布服务，不直接写入已发布状态。
4. 真实模型验收复用现有配置，使用合成输入、有限重试和调用回执。协议桩测试与真实模型测试分开，不因模型返回失败改成固定答案或放宽验证。
5. 行为缺陷先加失败回归，再做最小修复。任务串行推进；只读审查或单任务内无交叉写入的子范围可以并行。契约和生成产物由整合者统一同步。
6. 保留正常开发入口和发布流水线。候选构建、Docker smoke、安装升级、备份恢复、安全扫描与桌面验收使用自有隔离资源。宿主现有服务或端口不被接管。
7. 最终本地候选采用明确的 RC 标识及源码指纹；不修改历史 tag，不推送，不公开发布，不将未提交候选冒充正式 CI 构建。

## 原则核对

本计划保持桌面范围、普通会话、工作区授权、只读执行、职责分离、不可变版本、失败可见和凭据保护。来源和验收行均为合成；不查询未获授权的真实业务明细。已有公共契约与历史迁移不通过删除或降级验证绕过。

## 替代方案

- 不使用纯前端 mock 作为交付验收：无法证明权限、持久化、模型与执行链路。
- 不直接在既有测试工作区覆盖数据：无法可靠证明隔离与恢复，可能破坏用户工作。
- 不一次实现所有长期能力：会扩大当前收敛版的语义、权限和验收范围。

## 风险与应对

旧演示脚本可能依赖七类知识契约，需要改为五类知识而不是放宽生产验证。真实模型存在非确定性，保留失败记录并以固定测试集报告。构建和数据库集成较耗资源，限制并发并核对归属。最终全量门禁失败时修复或保留未完成状态，不降低断言。

大规模企业性能和真实业务正确性只能按实际证据声明；本次合成案例、既有规模基准和本地运行证据不替代这些承诺。

## 验证策略

基线与专项使用 `go test -count=1`、前端 Vitest、Node 脚本测试、真实 PostgreSQL 集成和公开 API 探针。真实模型通过正常应用服务调用。桌面使用 Playwright 1440x900、1024x768，不新增移动测试。

最终执行 `make check-source`、`make check-browser`、`make check-smoke`、`make security-check`、既有性能门禁和候选包校验；各脚本执行前先核对其清理范围、版本及环境假设。发现脚本依赖专用旧验收环境时修复隔离入口，不绕过其归属检查。
