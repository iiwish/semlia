# 收敛版 1.0 产品契约

| 字段 | 值 |
| --- | --- |

| 日期 | 2026-09-26 |

## 用户与目标

数据负责人通过正常桌面产品接入材料、整理五类知识、确认口径和独立审核发布。业务使用者基于已发布分析模型问数，核对结果、SQL、版本和来源，并反馈错误。应用工程师通过 REST、MCP 和 CLI 消费同一份受权限约束的知识。

## 范围

| 编号 | 要求 | 验收结果 |
| --- | --- | --- |
| V1-FR-001 | PostgreSQL 和现有支持格式的来源接入、快照与内容核对 | 合成输入可经正常接口发现和浏览，来源版本、失败与覆盖状态准确 |
| V1-FR-002 | 五类知识及已有结构化成员、计算规则、绑定和关联 | 业务对象、业务口径、指标、数据资产、分析模型可创建、编辑、核对引用 |
| V1-FR-003 | 验证、业务口径确认、独立审核、不可变发布和回滚 | 未确认、越权、自审和失效版本不得发布；历史可追溯 |

| V1-FR-007 | 本地自托管候选及维护路径 | 安装、升级、备份恢复、健康检查和候选产物验证有可重跑证据 |

## 非功能边界

- V1-NFR-001：保留工作区隔离、最小权限、职责分离、凭据保护、只读限制、限量、取消、幂等与审计；不增加测试后门。
- V1-NFR-002：仅验收 1440x900 和 1024x768；保留键盘、可见焦点、减少动效和合成数据披露。
- V1-NFR-003：固定测试输入和独立预期答案；模型只接收获授权的合成材料，不向模型提供评分答案。记录原始模型成功率、人工纠正和最终链路结果，失败不从分母剔除。
- V1-NFR-004：最终候选绑定源码指纹、构建版本、schema、模型配置标识和真实验证记录。既有性能基准和安全门禁必须运行；没有新证据的企业规模和可用性目标不作通过声明。

## 数据与执行授权

验收数据由项目生成，不要求用户提供真实业务数据。使用独立应用数据库、合成来源数据库、专用账号、目录和未占用端口；复用现有 OrbStack PostgreSQL，不修改其他项目资源或现有业务库。现有账号、来源、模型配置与凭据保留。

用户授权使用测试环境配置的模型供应商与模型，不设测试额度门槛。调用仅用于本契约的合成材料与问题，仍设置超时、有界重试和调用记录，防止失控循环；密钥和会话不进入日志或公开证据。

合成角色可以自动完成验收所需操作，但必须通过正常登录、权限与审核路径，并明确其不是实际业务负责人签署。合成验收不代表任意企业口径的准确性或生产运行 SLA。

## 不包含

无模型临时规划、完整独立成员映射治理、模型能力索引、长期记忆、多业务时区、自动发布、大量新连接器、通用 SQL 控制台、移动端、远程部署、Git 推送及公开发布不属于本次范围。现有不支持请求必须明确拒绝，不得伪装为成功。

## 完成条件

核心正常旅程及失败恢复均有自动验证和桌面证据；新发现阻断缺陷完成失败复现、修复、回归和独立评审；候选安装与恢复可复现；所有未验证项和已知限制清晰列出。最终候选保持待用户验收，不自动标记正式 1.0 已发布。

## 确认记录

用户明确同意收敛版 1.0，选择生成测试数据验收，授权本地操作与子代理，授权使用已配置模型，并确认开工。产品范围已确认；具体技术计划与任务图单独记录审批状态。
