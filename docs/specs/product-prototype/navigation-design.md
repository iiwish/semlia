# Semlia Prototype Navigation Design

## 元数据

| 字段 | 值 |
| --- | --- |

本文档定义 Semlia 桌面产品的菜单边界、任务入口和跨模块交互。领域模型保留完整的来源、revision、运行、知识块、证据、资产、变更、验证和 release；导航只呈现用户需要直接找到并持续操作的责任域与长期对象。

## 1. 产品导航原则

Semlia 使用“稳定业务对象 + 待办工作流 + 按需追溯”的交互模型。

- 系统处理阶段不直接成为同级菜单。
- 正常且无变化的后台运行静默归档，不要求用户巡视。
- 异常、风险和有意义的变化进入工作台待办，并形成可决策的变更事项。
- 中间产物在资产、变更事项和运行诊断中按上下文出现。
- 用户从一个变更事项即可理解触发来源、资产影响、证据、验证和消费者影响。

一个对象只有同时满足长期身份、可直接查找、独立权限或负责人、独立工作流中的大部分条件，才进入 contextual panel。其他对象作为页内 Tab、活动记录、详情或追溯引用。

## 2. 一级导航

Activity rail 从上到下排列：

1. 语义问答
2. 工作台
3. 知识资产
4. 变更与发布
5. 数据接入
6. 系统设置

前五项属于主功能区，系统设置固定在底部管理区。一级导航按用户任务组织：问答用于消费可信知识，工作台汇总个人待办和活动，知识资产承载长期语义对象，变更与发布负责审核和版本生效，数据接入管理来源与自动化。工作台只做跨域聚合，不复制各责任域的完整工作面。

## 3. 菜单树

| 一级菜单 | 二级入口 | 主任务 | 主要对象 |
| --- | --- | --- | --- |
| 语义问答 | 问答会话 | 使用已发布知识获得可追溯回答 | conversation、answer trace、citations |
| 工作台 | 我的待办、活动记录 | 处理跨域待办并观察重要系统活动 | work item、attention event |
| 知识资产 | 最近打开的资产 | 默认进入知识目录，以语义资产为主线管理关系与物理实现 | SemanticAsset、AssetRelation、PhysicalBinding、JoinContract |
| 变更与发布 | 变更事项、版本发布 | 审核变化并控制不可变版本生效 | change item、validation、release、binding |
| 数据接入 | 数据来源、接入自动化、执行记录 | 建立来源、配置自动化并诊断执行 | DataSource、automation policy、diagnostic run |
| 系统设置 | 成员、模型配置、接口与集成、审计与运行设置 | 管理成员目录、模型、低频平台配置和对外接口 | membership、model configuration、channel、audit |

全局搜索使用顶部搜索框和 `Command K`，不作为一级菜单。Contextual panel 只包含当前责任域内的长期页面或对象集合，状态筛选和局部视图使用主画布中的 segmented control、Tab 或搜索控件。

## 4. 工作台

工作台默认进入“我的待办”，而不是生命周期概览或指标 dashboard。

“我的待办”按风险和等待时间排列需要判断的事项，每个事项同时显示：

- 用户需要做出的决策。
- 触发来源，例如接入运行、消费反馈或人工编辑。
- 受影响资产和消费者。
- 当前风险与下一步。

“活动记录”汇总自动化运行、变更形成、版本发布和消费反馈。正常活动保留为低噪声记录；需要判断的异常同时进入我的待办，并可直接进入运行诊断或变更事项。工作台只保留摘要与深链，不在这里重复审核队列、版本清单或运行详情。

## 5. 数据接入

数据接入采用以下结构：

```text
数据接入
├── 数据来源
│   ├── 数据库连接
│   └── 文件导入
├── 接入自动化
│   └── 自动化策略
└── 执行记录
    └── 运行详情
```

“数据库连接 / 文件导入”是数据来源页内 Tab。接入自动化只承载可编辑的长期策略；执行记录作为独立二级页面承载运行历史和异常诊断，避免策略与事件混在同一页面。

单次运行详情保留输入快照、触发方式、构建方式、耗时、执行过程和结果引用。结果中的物理变化与证据用于追溯，结构化候选统一进入关联变更事项。SourceRevision 只出现在来源详情、运行详情和变更事项的来源上下文中。

构建任务固定一组 `SourceRevision` 作为输入，产出物理观察、`KnowledgeBlock`、`Evidence` 和结构化候选。构建运行不直接生成已发布 `SemanticAsset`。

## 6. 知识资产

知识资产以知识目录为默认工作面，contextual panel 只提供最近打开的资产快捷入口：

```text
知识资产
├── 最近打开（资产快捷入口）
└── 知识目录（资产中心清单）
    ├── 语义资产
    ├── 语义关系
    ├── PhysicalBinding
    └── JoinContract
```

知识目录使用一张全宽可筛选清单管理语义资产、已持久化语义关系、PhysicalBinding 和 JoinContract。语义资产是默认主行，关系与实现作为可寻址子对象归属于资产；搜索可以命中子对象并定位所属资产。类型是普通筛选条件，不形成独立页面或模式切换。选择语义关系后进入所属资产的“本体关系”上下文；选择 PhysicalBinding 或 JoinContract 后进入“实现”上下文，并定位具体对象。返回时保留目录查询、浏览位置和最近选择。

资产详情通过“概览、定义、本体关系、实现、可信度、交付与影响”六个任务视图回答当前资产 revision 是什么、处于哪个本体上下文、如何执行、为何可信、如何交付和影响谁。标题区同时显示稳定 key、revision 与 release。概览只展示核心语义摘要、阻断优先的生产判断和专业视图入口；完整定义、本体、实现、证据、验证和消费者版本约束进入对应视图。没有物理实现能力的业务概念隐藏“实现”，其余类型保留一致的信息架构并明确缺失实现的阻断原因。“本体”与“物理数据图谱”是领域投影和分析工具，不作为目录页面或用户必须切换的展示模式。

六视图由 `AssetTypeProfile` 专业化：定义页展示该类型的必填契约和内容模板，本体关系页应用该类型的关系政策，实现页应用绑定与 Join 要求，可信度页展示版本化类型门禁，交付与影响页使用类型专属空状态。Tab 名称和深链保持稳定，类型差异通过内容与能力条件表达。

知识块与证据是语义资产和变更事项的支撑材料，不作为用户必须经过的阶段页面：

- 资产详情的“可信度”Tab 展示支持当前定义的知识块、字段证据、策略和验证运行。
- 变更事项展示本次决策关联的证据、来源运行和验证结果。
- 问答引用直接打开关联资产的证据上下文。
- 专业排查可从运行详情追溯证据批次和物理变化记录。

## 7. 变更与发布

变更与发布以“变更事项”为主要工作单位。每个事项在同一工作面中展示：

1. 触发来源和关联运行。
2. 受影响资产。
3. 结构化字段差异。
4. 关联知识与证据。
5. 验证结果。
6. 消费者影响。
7. 风险等级和决策动作。

变更事项默认使用全宽决策列表，横向比较风险、验证完成度、消费影响、触发来源和等待状态。用户选择单个事项后进入独立详情，再检查补丁和证据并作出决定；列表不同时承载完整详情。

验证运行不作为独立菜单；验证结果属于变更事项的决策证据。批准后的候选进入“版本发布”，由不可变 manifest、兼容性约束和 binding 切换控制生效与回滚。版本详情直接列出使用该版本的应用和绑定，消费关系不再形成独立一级菜单。

版本发布默认分为待发布候选和不可变版本历史。候选区只呈现当前可执行发布动作，版本历史使用全宽列表支持版本间比较；用户进入版本详情后查看 manifest、应用绑定与回滚边界。

对外接口、消费关系和运行反馈按责任归位：

- REST、MCP、CLI 与 SDK 的平台配置进入系统设置的“接口与集成”。
- 资产使用方和版本绑定分别进入资产详情的“交付与影响”和版本详情。
- 解析失败、版本漂移和消费异常进入工作台的“活动记录”；需要用户判断时，同时形成“我的待办”或关联变更事项。

## 8. 导航层级

| 层级 | 职责 | 允许内容 | 不允许内容 |
| --- | --- | --- | --- |
| Activity rail | 切换稳定产品责任域 | 一级菜单、全局管理入口 | 运行状态、临时步骤、单一批次 |
| Context panel | 选择当前责任域内的长期对象或页面 | 最近对象、二级页面、会话、保存视图 | 后台处理阶段、局部筛选 |
| Main canvas | 完成当前任务并检查上下文 | tabs、filters、commands、details、diff、trace | 重复主导航、要求用户手工拼接流水线 |

跨模块动作使用主内容区中的明确命令，并保留当前对象上下文。返回入口回到发起动作的列表或工作队列。运行、证据和 validation 允许通过全局搜索直接查找，但搜索结果进入所属对象的详情上下文。

## 9. 验收标准

- 工作台默认展示可推进的工作，而不是生命周期阶段。
- 数据接入 contextual panel 包含“数据来源”“接入自动化”和“执行记录”。
- 构建运行可以从自动化策略、执行记录和工作台异常进入，运行详情不形成新的导航层级。
- 知识资产 contextual panel 只显示最近打开的资产；一级菜单默认进入知识目录，语义资产作为主行，关系、PhysicalBinding 和 JoinContract 作为可展开子对象使用同一张清单展示。
- 变更与发布 contextual panel 只包含“变更事项”和“版本发布”。
- 变更事项同时展示来源、资产、证据、验证和消费影响。
- 一级导航不设置“语义交付”；接口、绑定和运行反馈可以在各自责任域内直接找到。
- 正常运行不会制造待办；异常运行可以一键进入诊断和关联变更事项。
- 1440x900 与 1024x768 下无文本溢出、错位或控件重叠。
- 导航、Tab、筛选、列表和对话框支持键盘、可见焦点与 reduced-motion。
