## 技术方案

1. 在 `examples/resume-demo/` 定义版本化合成零售数据合同和生成器。使用固定种子、固定 90 天区间及整数分表示金额，生成 300 名客户、3000 笔订单、订单明细、商品和退款。全部姓名、标识和交易为合成内容，不含真实个人信息或凭据。
2. 生成 PostgreSQL DDL/数据及 SQL 来源工件、业务规则说明和独立预期汇总。客户与订单关系、明细汇总、支付状态及退款上限必须一致。生成器不依赖墙钟时间，不因重跑改变内容。
3. 使用专属本地演示数据库、内容目录、工件目录及未占用端口运行正常 `cmd/semlia` server/worker，不使用 `internal/testsupport/productionacceptance` 作为演示服务器。开发实例 18080/18081 与既有数据库保持不变。仅应用正常数据库迁移，不新增产品迁移。
4. PostgreSQL 使用 OrbStack 内经归属检查的既有实例，创建明确命名且具有所有权记录的独立演示数据库和专用凭据。应用原生启动，不构建 Docker 应用镜像，不改现有数据库、共享角色、网络或实例级设置。数据库创建权限不足或归属不明时停止，不绕过保护。
5. 成果展示区和现场操作区均为正常工作区。初始化使用正式管理员命令；成员创建、权限分配、来源发现、生产、业务确认、验证、审核、发布及回滚使用正常接口和真实会话。作者、审核者、发布者为分离账号，不使用伪造主体请求头，不直接写治理或 release 数据表。
6. 演示业务源的合成表允许生成器在专属来源数据库中导入。Semlia 的来源发现首先使用现有 SQL 工件路径，确保数据包可移植且不扩展连接器；业务行及独立预期结果用于数据自洽校验，不声称已验证真实数值查询能力。
7. 初始化器记录输入摘要、目标归属及服务端对象 ID。相同输入重跑不产生重复来源、资产或发布；中断后先查询服务端事实再恢复，不凭客户端日志猜测成功。版本不匹配时拒绝覆盖，不提供无条件清库命令。
8. 运行配置与随机账号密码保存在 `.semlia/resume-demo/` 的受保护文件中，不写入命令参数、仓库或普通日志。公开样例和证据不包含 Cookie、CSRF token、数据库口令或账号密码。

## 演示内容

| 场景 | 初始条件 | 可核对结果 |
| --- | --- | --- |
| 首次生产 | 现场操作区仅有来源、身份和配置，无语义资产或发布 | 发现候选，经人工建设、业务确认、验证、独立审核后发布 |

成果展示区由初始化器走完上述真实流程后保留可浏览状态。现场操作区的完整演练在独立验证副本完成，交付的现场操作区保持未开始生产。测试产生的发布不混入现场操作区。
