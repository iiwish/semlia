# 五类知识原型实施计划

状态：Confirmed。用户已确认执行计划、本地原型数据清理范围和子代理分工。采用 Delegated Execute，主任务负责整合与验收。

## 产品契约

Semlia 的一级知识类型为业务对象、业务口径、指标、数据资产、分析模型。属性和字段是成员，基础聚合与派生计算是指标内部类型。原型不提供旧七类数据的迁移适配或兼容入口。

知识编辑、AI 建议、API、持久化、验证、发布和消费采用相同结构。可保存未完成草稿，但未满足类型契约、成员引用、业务确认和实现验证的知识不能发布执行。

## 实施边界

- 保留现有来源采集、授权、独立审核、不可变发布和只读执行机制。
- 数据清理仅针对本地 Semlia 原型中不兼容的语义知识及其派生生产、发布、检索和查询记录。先核对外键依赖与影响计数，并保存本地恢复快照。
- 保留工作区、账号、角色、会话、模型配置、来源连接和凭据、来源快照、上传材料及接入计划。不得连接源数据库执行清理，不修改共享基础设施。
- 工作树已有修改继续保留；不创建兼容层，不重写无关模块，不部署到远程环境。
- 桌面维持 1440x900、1024x768；保留中性画布、现有字体与颜色、8px 以内卡片圆角、键盘焦点和减少动态效果。

## 执行包要求

每个任务以本文件、`knowledge-types.md`、`case-walkthrough.md`、`data-assets-ontology-lineage.md` 和 `AGENTS.md` 为输入。执行前固定本任务接口、允许路径与依赖，检查已有改动；新增行为先添加失败测试，再实现和回归。不得将说明性 JSON 原样当作生产协议，不以自由 SQL 或自然语言声明替代结构化执行规则。

结构验证覆盖成员 ID 重复、错误类型、未知字段、错误版本、非法依赖、循环和缺失实现。发布验证继续固定完整集合及审核归因，不能以原型为由跳过授权和职责分离。

## 验证命令

- `go test ./internal/domain/semantic ./internal/domain/governance ./internal/domain/distribution ./internal/domain/execution`
- `go test ./internal/application/... ./internal/platform/http/...`
- `make contracts-check`、`make db-generate-check`
- `pnpm --dir web typecheck`、`pnpm --dir web test`、`pnpm --dir web build`
- 独立数据库集成测试及桌面端到端验收，最后运行 `make check-source`。

## 验收场景

同一组已发布知识支持客单价总量、按区域分组和跨期比较。分子分母同范围，汇总重算；客户首次支付采用真实历史属性；多对一连接必须证明右侧键唯一，避免扇出。

负向覆盖零分母、空结果、未知成员、日期边界、来源失效、缺少绑定、多个模型歧义、重复客户键、越权与未发布规则。不适用实现必须澄清或拒绝，不能返回样例答案。

本地清理后验证保留的账号、权限、连接与模型配置可用。合成数据明确标识，真实来源对账与合成案例结果分别报告。交付证据记录测试命令、截图、清理影响、已验证能力和剩余限制，不以文档或截图代替真实执行证明。
