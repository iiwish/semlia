# 可信知识驱动问数

## 产品契约

Semlia 是用可信语义知识驱动问数的产品，治理是保障，不是用户的主要工作。
用户通过数据接入、知识整理与确认、问数、结果核对与纠正完成闭环。
知识包括业务实体与关系、字段含义、指标及计算口径，均保留来源依据。

## 本轮执行范围

- 主导航为问数、知识库、待办、数据接入；系统设置独立保留。
- 待办聚合已授权的知识确认与协作任务，提供待处理、我发起、已处理视图。知识确认是处理详情，不是并列任务入口。
- 知识整理记录和发布历史属于知识库；旧知识确认、版本、个人待办链接继续可访问。
- 知识详情保留入口归属：来自草稿与整理的详情归属知识库并返回草稿列表；来自待办的详情返回原待办范围。入口信息写入路由，刷新和浏览器前进后退保持一致。
- 批量审核是待办中的辅助操作，只展示审核批次；单条知识的处理入口为待办，发布历史仅在知识库的发布记录中展示。旧单条提案深链继续可访问，原审核和发布权限不变。
- 数据接入的二级菜单为数据来源、接入计划、运行记录；文件入口称为导入文件；知识库的二级区域总标题为知识库。
- 知识行动直接派生自生产操作的当前业务状态，不创建第二套完成状态或人工完成按钮。知识记录没有个人分配契约，不将可见记录称为已分配给我的任务。
- 一个生产集合对应一个知识行动，其关联提案的审核与验证提醒在聚合时去重；被后继操作替代、已发布、无实质变化的记录退出待处理。验证中的系统进度保留在整理记录。
- 聚合分别沿用生产与工作台接口的逐对象授权、分页和错误边界；只对完整加载成功的集合显示确定计数，不以部分数据或请求失败宣称清空待办。
- 定义、范围和业务口径缺失以中文行动提示呈现，校验器版本、摘要、规则代码和原始诊断放在可展开详情中。
- 知识确认列表使用对应版本的知识名称，不以内部记录 ID 作为主标题。
- 已确认没有发布记录时，问数显示空状态并直达知识确认，不调用模型或展示无依据的示例指标。
- 本地启用已实现的语义生产服务，不自动授予模型调用权限、不启用批量自动生成、不代替人工确认或发布。
- 保留现有权限、职责分离、幂等、版本锁和发布约束；不改动未提交的无关实现。
- 不增加连接器、查询引擎或第二套治理模型。

## 界面约束

沿用现有中性背景、颜色和字体；主内容不新增装饰性容器。桌面 1440x900、紧凑桌面 1024x768；保留键盘焦点和减少动态效果。用现有 Lucide 图标。首屏优先展示知识内容、待处理原因和下一步动作；原始 ID 只作为详情信息。

## 验证

导航与旧链接回归、错误映射与未知错误安全回退、未通过校验不得批准、测试及 TypeScript 检查、两种桌面尺寸截图、本地生产记录接口与服务就绪检查。

## 真实闭环验收标准

在一个获授权的真实来源中选择 2–3 张表、一份业务口径和一个指标，通过界面完成接入、生成、确认、审核与发布，再用三个真实问题取数，与人工 SQL 对账。没有确定来源、只读执行连接和模型调用预算时，不用测试结果代替这项验收，不自动开启全量生成。
