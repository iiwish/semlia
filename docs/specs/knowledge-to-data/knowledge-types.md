# 知识对象、成员与实现契约

本文定义 Semlia 的知识模型及当前原型的覆盖范围。主要知识对象为业务对象、业务口径、指标、数据资产和分析模型。属性、判定规则、聚合表达式、关系和绑定具有明确类型与引用身份，但不要求用户把它们逐个创建为一级知识。第 1 至 4 节描述产品契约，当前实现范围以第 5 节及验收证据为准，不改变发布权限。

## 1. 设计原则

分类依据是独立的业务职责和维护价值，而不是执行引擎的构件清单。每份知识自身保存名称、定义、别名、范围、负责人和证据，不要求再建立同名“概念”解释它。

- 业务对象回答“是谁”，数据资产回答“这份数据是什么”，分析模型回答“这个场景怎样组合数据”；三者不合并。
- 属性归属于业务对象或事件，保留稳定成员身份、值类型和时间语义。字段只在确有业务需要时整理为语义属性，不全库自动创建一级知识。
- 业务口径保存独立术语及可选的判定规则。定义与条件在同一知识修订中管理，不重复维护同名概念和分群。
- 指标统一管理基础聚合与派生计算。行级属性、聚合表达式和聚合后计算必须有不同类型及验证规则。
- 来源结构、知识定义和消费产物分别管理；SQL、反馈和候选解释不自动成为已发布知识。
- 成员绑定与关联契约独立验证、发布和寻址，分析模型与临时查询计划共同引用，不由模型独占。
- 模型按真实场景和复用价值沉淀，不按指标、口径、月份或地区的组合枚举。无模型但有完整获准依据时允许受控规划；依据不足时只形成候选。

依据：[SSOT](../../SSOT.md)、[语义资产设计](../semantic-assets/semantic-asset-design.md)。

## 2. 五类主要知识对象

下列标识用于知识分类；具体请求结构以 OpenAPI 与生产校验为准。本文的阅读示例不是 API 请求体，实现边界见第 5 节。

| 对象 | 目标标识 | 应包含的信息 | 说明性例子 |
| --- | --- | --- | --- |
| 业务对象 | `business_object` | 自身定义、对象粒度、业务键、身份合并策略、生命周期、可寻址属性、业务关系 | 客户、订单；客户当前区域和首次有效支付日期属于客户属性 |
| 业务口径 | `business_term` | 独立术语的定义、别名、包含/排除范围、正反例；可选的适用对象、结构化条件、参数和依赖 | 老客户、有效订单；定义与判定规则共同管理 |
| 指标 | `metric` | 基础/派生类型、输入属性或指标、聚合或公式、过滤、时间窗口、单位、空值、零分母及可加性 | 实付总金额、有效订单数为基础指标；客单价为派生指标 |
| 数据资产 | `data_asset` | 来源版本、数据集和字段成员引用、用途、覆盖、字段解释、粒度、身份、时间、使用规则、质量与加工实现 | 统一客户档案、电商注册账号数据、客户每日快照 |
| 分析模型 | `analysis_model` | 场景、基础对象与粒度、公开属性、默认时间、适用约束、资产与独立绑定/关联引用、经验证的能力索引引用 | 订单分析复用订单与客户的可靠关联，服务总体、区域和老客户分析 |

业务对象“客户”自身解释客户含义；指标“客单价”自身解释计算口径。不因需要中文说明而额外创建同名业务口径。独立口径用于有复用价值的术语或条件，不承载通用 ETL、权限策略或任意 SQL 脚本。

### 2.1 业务对象与属性

属性包含稳定成员 ID、所属对象、名称、定义、值类型、值域/编码、空值语义、粒度、历史策略及适用的实现引用。成员引用固定为 `asset_id + revision_id + member_id`，不得仅凭“首次支付日期”等名称匹配。成员随所属资产修订不可变发布；改名不改变成员身份，删除或改变含义需评估所有引用。

“维度”表示属性在查询中承担分组、筛选或时间角色，不是必须单独维护的一级知识。数值属性也不等于指标：订单实付金额是行级输入，实付总金额是聚合结果。首次有效支付日期可以由历史交易聚合得到，但对外是客户粒度的属性；加工必须有独立、已验证的实现，不能在上月交易里临时取最小值冒充历史首次支付。

共享日历、区域层级等按真实复用需求管理共享定义，使用方引用同一版本，不复制规则；首轮不要求把每个字段都提升为共享定义。

### 2.2 业务口径与判定规则

业务口径有两种能力状态：仅用于解释的术语，以及具有可执行判定规则的口径。后者的规则必须明确适用对象、结构化布尔表达式、依赖的属性或指标、参数名称与类型、空值行为、时间和有效范围。自然语言解释不能自动授权筛选。

“老客户”在同一份知识中保存定义与 `客户.首次有效支付日期 < 统计期开始日` 条件，引用客户属性，不另建同名分群。“统计期开始日”的类型属于规则定义，具体日期属于查询参数。客户区域等于华东通常只是属性筛选，不为每次取值创建知识。

涉及“近 30 天支付至少两次”的条件时，需明确客户粒度、窗口和聚合阶段；不能把聚合判定简单拼成行级 WHERE。缺少相应执行能力时阻断。名单快照、成员进出、刷新与营销触达是专门的群体管理需求，不属于首轮必备知识类型。

### 2.3 指标的计算类型

| 结构 | 输入与输出 | 必须校验 |
| --- | --- | --- |
| 业务属性 | 单个对象或事件的取值，例如订单实付金额 | 对象粒度、类型、单位、时间与来源 |
| 基础指标 `aggregate` | 按明确范围聚合属性，例如 SUM 实付金额、COUNT DISTINCT 订单键 | 聚合函数、去重身份、过滤、空值、币种和可加性 |
| 派生指标 `derived` | 引用基础或其他指标进行计算，例如客单价 | 依赖无环、统一筛选范围、计算顺序、单位、零分母及汇总重算 |

客单价在本例定义为同范围实付总金额除以有效订单数，真实企业口径需确认。跨区域或跨期汇总必须重新计算分子分母，不直接累加或平均各组比率。基础与派生共享指标身份和治理机制，内部表达式类型不能混用。度量是执行适配中的聚合构件，不是用户必须额外创建的同名资产。

### 2.4 数据资产与分析模型

来源层保留观察到的表、字段、类型、约束、注释与 revision。数据资产引用这些对象及经确认的加工实现，补充用途、覆盖、粒度、字段业务义和限制，不复制事实明细或第二套原始结构。

数据资产成员解释一份具体数据；业务对象属性表达可跨实现复用的业务含义。独立成员绑定将两者连接。分析模型引用可兼容的数据资产、绑定与关联契约，固定场景、粒度、时间默认值和使用限制，不复制对象定义、指标公式或绑定记录。多张客户表不能因同名而互换；一个资产由多表实现时，必须有明确、经验证的加工或视图契约。

有两份数据资产不自动生成模型。真实试点、常用报表或已有 SQL 暴露复用需求后，AI 提出组合草稿，由负责人确认语义与实现，经过验证和独立审核发布。月份、地区、筛选组合变化只改变临时计划；历史语义、身份体系、粒度或使用范围有实质差异时才评估独立模型或实现。

模型的可计算指标和可用口径由版本化依赖、绑定与执行能力校验形成能力索引。索引是可重建的检索投影，不重复维护公式，也不是独立执行授权。新增指标可复用既有模型配置，依赖检查通过后更新对应发布版本的索引，不复制模型；失效或版本不匹配的索引不能用于放行。

## 3. 共有信息与实现引用

所有知识具有稳定身份、名称与定义、业务域和适用范围、负责人、来源证据、不可变修订和发布状态。证据、责任、验证、发布仍按独立对象管理，详情和 AI 上下文组合展示，不要求存为一张大表。

| 位置 | 保存的引用 |
| --- | --- |
| 业务口径 | 适用业务对象及属性/指标引用、条件与参数，不列出所有候选客户表 |
| 基础与派生指标 | 属性输入或指标依赖、口径引用、时间与适用范围 |
| 分析模型实现 | 兼容的数据资产 revision、独立绑定与关联的 ID/revision，以及场景、默认值和使用约束 |
| 成员绑定 | 独立记录 ID/revision；业务对象成员到数据资产成员的映射、转换/物理绑定、范围、证据和验证 |
| 关联契约 | 独立记录 ID/revision；数据资产端点、身份、键对、连接方式、基数、粒度、时间与必要过滤 |
| 数据资产实现 | 来源 revision、数据集 ID、字段 ID、加工工件和验证记录 |
| 临时查询计划 | 本次需要的知识、来源、绑定、关联、参数与可选模型引用，执行前校验和审计依据 |

绑定与关联是基础实现记录，不要求增加第六种面向用户的知识类型，也不必依附模型才能审核发布。记录包含工作区、稳定 ID、不可变修订、责任人、适用范围、来源证据、验证结果和发布状态；模型与无模型规划使用同一份获准记录。修改产生新修订，撤销或来源变化使相关模型索引、待执行计划进入重验。

实际表名、字段名由绑定引用的来源版本解析。字段重命名、删改、类型或含义变化必须检查兼容性并重新验证，不因 ID 稳定自动认定实现有效。计划在一致的 release 范围内展开必要依赖并固定版本，模型引用可为空；权限不足、绑定不完整或多实现歧义时澄清或阻断。无模型规划不能绕过场景要求使用指定模型的政策。

业务“订单属于客户”与物理 Join 分开记录。语义关系描述端点、方向和业务约束；JoinContract 固定数据集、键对、连接方式、基数、左右粒度、必要过滤、有效范围与扇出验证。数据血缘、语义依赖和证据溯源分别记录，通过版本化映射连接。

完整案例见[数据资产、本体与血缘](data-assets-ontology-lineage.md)。[定义结构示例](knowledge-definition-examples.json)包含五类对象、对象属性、判定规则、基础与派生指标的 JSON 阅读投影。它不是 JSON Schema、生产请求体或完整可执行依赖图，示例中的未知信息与外部引用不得用于发布取数。

## 4. 生产与消费边界

| 分组 | 定位 |
| --- | --- |
| 原始输入 | 数据库结构、文档、SQL、来源快照是调查材料，不是已确认含义 |
| 知识与成员 | 五类知识、属性、条件和计算规格保存可引用的业务含义 |
| 实现与治理 | 绑定、键、粒度、连接、证据、验证及发布控制可用性 |
| 消费产物 | 解析计划、SQL、参数及答案是本次使用产物，不自动反写为权威知识 |
| 用户偏好 | 在当前工作区对该用户生效的个性化配置，不新增一级业务知识类型，不覆盖业务口径或权限 |

知识保存结构化公式、条件、参数定义与实现映射；问题提供具体时间、区域等参数。执行适配器根据经验证的解析计划生成 SQL，不要求每个问题预存整段模板。SQL 工件可作为来源、实现或证据，但需经过相应确认，不能因执行成功就覆盖业务口径。

对话可分别形成用户偏好与系统通用知识候选。偏好需用户明确要求记住或确认，可修改、删除和停用；通用候选在共享授权、证据核验与独立审核发布后，按获准业务范围复用，仍归入五类知识及独立实现记录。一次查询选择不默认长期保存，个人对话不直接进入共享知识。详见[对话反馈设计](data-assets-ontology-lineage.md#8-对话反馈用户偏好与通用知识)。

| 查询条件 | 处理方式 | 执行边界 |
| --- | --- | --- |
| 有适用且获准的模型 | 优先复用模型配置，按完整问题展开必要依赖 | 模型命中不替代计划校验 |
| 无适用模型，所需映射与关联已确认发布 | LLM 在授权候选和规划预算内组装临时计划 | 不创建模型；知识、来源、关系及整条计划仍需兼容与执行校验 |
| 依据不足、语义歧义或策略禁止 | 形成具体缺口、澄清问题或建模候选 | 不直接取数，不临时编造未发布映射或连接 |

LLM 只提出计划或候选，受控解析器和执行适配器负责校验与执行。结构完整不证明业务正确；必须检查身份、时间语义、必要过滤、完整连接路径的基数与扇出、权限和资源预算。没有命名模型不等于缺少依据，也不赋予 LLM 建立权威关系或发布知识的权限。临时计划按必要审计与保留策略管理，只有复用价值明确且通过确认、验证和独立审核时才沉淀为模型。

完整加工与消费案例见[老客户客单价的知识链路](case-walkthrough.md)，逐步列出材料、知识草稿、成员绑定、发布版本、取数计划和结果的输入输出。

## 5. 当前原型覆盖

API、生产校验、数据库和知识编辑器采用 `business_object business_term metric data_asset analysis_model` 五种一级类型。`spec` 保存专属结构，成员具有稳定 ID；引用固定 asset、revision、release 及可选 member。草稿允许不完整结构，发布校验拒绝不完整结构、错误成员、错误类型和未发布引用。`knowledge-definition-examples.json` 是设计阅读投影，不是生产请求体。

| 范围 | 原型实现与限制 |
| --- | --- |
| 知识管理 | 五类筛选、创建、结构化编辑与详情；对象属性和数据字段为成员，基础聚合与派生计算为指标内部类型 |
| 来源与实现 | 数据资产固定验证通过的来源快照及表字段版本；独立 PhysicalBinding 和 JoinContract 提供执行依据，模型 spec 保存成员映射 |
| 模型选择 | 用指标、分组、口径、筛选和时间的完整需求匹配已发布模型；没有适用模型或存在歧义时拒绝执行 |
| 计算 | 封闭表达式、基础聚合、聚合后派生计算、汇总重算；基础业务键非空且唯一，成员空值策略生效；支持无歧义的受控内/左连接，多对一和一对一需通过右侧键唯一性检查 |
| 时间 | 查询采用 UTC 和左闭右开期间，可按日、周、月、季度、年分组；规则参数 `period_start` 随统计桶变化 |
| 反馈与证据 | 精确选择知识及成员纠错；解析偏差仅修改本次问题；结果区展示模型、版本、SQL 与参数，不把执行时间当作来源业务新鲜度 |

完整的独立成员映射生命周期、可重建能力索引、无模型规划、聚合阶段口径和多时区业务日历属于目标设计，不在本轮可执行范围内。未知来源业务数据时间明确显示未知；结构通过和执行成功都不能替代业务确认、证据及独立审核。

原型不提供七类历史知识迁移或兼容适配。经用户授权，本地不兼容知识及派生记录可在停服、恢复快照和保留数据指纹核对后清理；账号、角色、会话、模型配置、来源连接与凭据、快照和上传材料必须保留，不清理源数据库。

核对依据：[生产内容校验](../../../internal/domain/governance/production_schema.go)、[生产 OpenAPI](../../../api/openapi/semlia.v1.yaml)、[知识编辑器](../../../web/src/SemanticProductionPanel.tsx)、[实施计划](prototype-optimization-plan.md)。

## 6. 实施与验收重点

以一个真实问题验证模型，不以分类数或字段数验收：

1. 一个客户对象自身解释客户含义，区域和首次支付日期作为可引用成员；无需创建同名概念和所有源字段的一级知识。
2. 一份老客户口径包含定义与判定规则，版本一致；月份变化只改变参数，未确认的规则不能用于查询。
3. 订单金额属性、基础聚合指标、客单价派生指标类型明确；分子分母同范围，跨组重算正确。
4. 多份客户相关数据资产的身份、粒度、时间和覆盖差异可见；模型复用与无模型规划都通过获准绑定选数据，歧义必须澄清。
5. 切换底层来源不重写业务定义，但必须验证成员、键、时间、Join、权限与语义等价性；旧版本可复现。
6. 属性、口径或来源变化可以沿成员依赖、绑定和血缘定位待重验指标与模型，权限边界保持一致。
7. API、存储、编辑器、发布校验及适配器一致，并与人工基准 SQL 对账；文档和示意图不等于实现完成。
8. 相同问题在模型复用和无模型规划两条路径上按同一快照对账；未知关联不能执行，模型政策与权限不能被回退路径绕过。
9. 改变月份、区域或问法不新增模型；反复使用或 SQL 成功不自动发布知识，只有明确复用价值的候选进入审核。
