Semlia / Knowledge Governance

从万表证据到可信使用

离线构建可信语义，在线解析表、口径与 Join，全程绑定证据和版本。

治理原则：系统自动发现、验证和分流；新工作区默认人工发布，只有显式授权的低风险范围可以自动发布。

五层主链路

来源形成证据，证据形成候选，只有治理后的版本可以进入生产使用

L1 / Source

企业数据来源

只读连接仓库 Catalog、DDL/View SQL、dbt/ETL、血缘、文档与可选 Cube。

产物：Source Revision
L2 / Evidence

物理图谱与证据

解析表、字段、SQL、血缘、键、粒度和 Join 观察，抽取可引用知识单元。

产物：Physical Graph + Evidence
L3 / Semantics

语义资产

形成稳定定义、指标口径、本体、物理绑定、粒度和受治理 JoinContract。

产物：Asset + Ontology + Contract
L4 / Governance

治理发布

只审核相对已发布基线的变化，验证后形成不可变版本。

产物：可信 Release
L5 / Delivery

解析与交付

基于明确 Release 解析语义、物理绑定和 Join，再向人、应用与 AI 交付。

产物：Resolved Plan + Provenance
来源不等于事实：抽取内容必须带出处。
观察不等于定义：查询历史和 Profile 只能作为证据。
候选不等于发布：LLM 输出必须经过验证和治理。
使用必须绑定版本：生产消费只读取明确 Release。

L4 如何减少人工审核

审核变化，不重复阅读资产全文

结构化 Diff 无实质变化直接忽略
→
规则与测试 Schema、编译、权限、影响
→
风险与策略路由 不确定或失败一律降级

策略内自动处理

G2 / G3

条件：限定资产范围、证据完整、验证通过、管理员显式授权。

例如：结果不变的描述、别名和证据刷新。

批量确认

Same Pattern

条件：同一来源与风险原因，可查看样本和最大风险项。

例如：字段映射、owner、术语合并。

专家审核

High Risk

条件：改变计算、权限、契约，或存在冲突与失败。

例如：财务口径、删除、Breaking Change。

不可变 Release 低风险项接受抽样审计；运行异常可停止、回滚或冻结对应策略。

Agent 如何找对表、口径与 Join

LLM 负责理解问题，不拥有自由选表、拼 Join 或执行任意 SQL 的权限

1. 受控问题 身份、用途、时间范围、业务术语与稳定 Release。
2. 语义解析 检索已发布指标、实体、维度和候选解释。
3. 物理绑定 解析表、字段、粒度、时间字段与受治理 JoinContract。
4. 计划验证 校验权限、基数、扇出、过滤、兼容性和成本。
5. 执行适配器 委托给 Cube 或受控 SQL 引擎；Semlia 不自建查询内核。
6. 可解释结果 返回结果、口径、表字段、Join、Release 和证据。
不确定性门禁 资产歧义、证据不足、Join 未发布、粒度冲突或验证失败时，必须拒绝执行或请求澄清，不能静默猜测。

使用反馈只形成新待办或提案

观察信号不是事实，不会直接改写知识、Join 或已经发布的语义

真实使用 成功、失败、反馈、事故
→
版本归因 Asset / Release / Consumer
→
治理待办 可解释规则与证据
→
重新进入 L4 验证、分流、发布
