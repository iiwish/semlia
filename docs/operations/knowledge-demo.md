# 五类知识演示数据

## 入口

打开本地服务输出的页面地址，在右上角账户菜单中选择 **合成演示 · 订单语义平台**。实际部署地址、登录凭据与部署记录由环境维护者通过独立渠道提供，不进入版本库。

演示工作区 `demo-202609-commerce` 与 `Semantic Core` 隔离。来源、知识定义和模拟审核记录明确标注为合成演示，不代表真实业务口径、真人审批或生产可用性认证。演示角色没有登录账号。

## 内容

| 类型 | 对象 |
| --- | --- |
| 业务对象 | 订单、客户 |
| 业务口径 | 有效订单、老客户 |
| 指标 | 有效支付金额、有效订单数、客单价 |
| 数据资产 | 订单演示数据、客户演示数据 |
| 分析模型 | 老客户客单价分析 |

包含 20 条目录关系、2 个已发布物理绑定和 1 个多对一连接契约。知识引用固定实际发布版本，而不是悬空示例 ID。种子程序通过正常校验、模拟角色审核和发布服务装载知识，所有审核说明标注模拟性质。

`数据接入 → 合成演示：订单与客户 → 内容` 提供两张 PostgreSQL 表的字段结构。来源元数据是固定合成模式的声明导入，不伪造外部采集运行记录。

`合成演示：订单样本（7 笔）` 和 `合成演示：客户样本（4 位）` 是通过正常文件导入创建的 CSV 来源，可以在内容页直接查看业务行。它们与查询数据库使用相同的合成样本；PostgreSQL 来源本身的业务行预览不在当前界面支持范围内。

## 演算

问题：**2026 年 8 月，华东地区老客户的客单价是多少？**

- 时间范围：UTC `[2026-08-01, 2026-09-01)`。
- 客户区域：当前值；首次有效支付时间：已确认的全历史合成属性。
- 老客户：首次有效支付时间早于查询起始时间。
- 有效订单：仅对本样本使用 `is_valid = 1`，不是企业通用规则。
- 七笔订单中纳入 O01、O02、O03，涉及两位客户。
- 金额 600 元，订单数 3，客单价 **200 元/单**。
- 分母为零返回空值，汇总时重新计算金额与订单数。

样本逐行对应 [设计稿演算样本](../briefings/2026-09-semantic-platform/case-example.json)。种子程序使用实际已发布语义模型编译 SQL，通过独立只读数据库账号执行并验证结果；不会将期望值直接当作查询结果。

自然语言模型配置不随演示数据复制。演示工作区需要单独配置模型才能进行自然语言问数；种子程序的结构化查询校验不调用外部模型。

## 初始化

先启动本地原生服务与工作进程，然后执行：

```sh
node scripts/dev/seed-knowledge-demo.mjs --apply
```

首次写入执行来源配置后，重启原生服务：

```sh
node scripts/dev/native.mjs down
node scripts/dev/native.mjs up
```

脚本仅接受本仓库拥有的 `semlia-local` PostgreSQL 容器及 `127.0.0.1:5433/semlia`。它添加独立的 `semlia_demo_202609` 数据库、同名只读角色及演示工作区，不重置现有登录账号、不清理现有知识、不修改真实业务来源。

CSV 预览来源通过界面 `数据接入 → 导入文件` 一次性导入 `scripts/demo/knowledge-202609/orders.csv` 和 `customers.csv`，来源名称使用上述合成演示名称。初始化脚本不重复上传文件。

重复执行复用本地所有权回执，不重复添加知识或关系，不轮换已有凭据。发生所有权、配置或凭据冲突时停止，不接管同名对象。首次工作区创建等步骤若在写入回执前中断，需要检查已创建对象；脚本不自动删除或猜测接管。

本地私有目录 `.semlia/demo-202609/` 包含初始化前备份 `before-demo.dump`、恢复执行用回执 `state.json`、结构化查询 `demo.json` 和实际查询证据 `execution-proof.json`。其中回执包含仅供合成数据库使用的密码，目录与文件按私有权限保存，不能提交到版本库。来源预览凭据在应用数据库中使用现有 AES-GCM 机制加密。
