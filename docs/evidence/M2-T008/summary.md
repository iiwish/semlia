## Delivered

- Migration `000007_m2_governance_objects` (+ down): the four D-014 governance objects as workspace-scoped tables — `physical_bindings`, `model_grains`, `entity_keys`, `join_contracts` — each carrying the M1/T002 discipline: UUIDv7 identity CHECK, `workspaces` FK on the aggregate root, `UNIQUE (workspace_id, id)`, `version integer NOT NULL DEFAULT 1` (the release-manifest pin), a flexible `content jsonb` object column, `created_by/created_at/updated_at`, listing and lookup indexes, and a shared `enforce_governed_object_version_bump` trigger that freezes identity columns and requires every UPDATE to bump the version by exactly one (defense in depth behind the governed application path). Reference integrity composes against the M1 physical graph with composite workspace-scoped FKs: bindings reference `semantic_assets`, `physical_datasets` and `physical_fields`; join contracts reference both `physical_datasets` sides; model grains may reference an `evidence_artifacts` row via `documented_by`. The downgrade drops only the four tables plus the one new function, restores the T002 `proposals_target_object_type_check` vocabulary, and removes the proposals that the new vocabulary made possible; M0/M1/T001/T002 rows stay untouched (proven by the populated suites).
- Uniqueness of active bindings: one ACTIVE binding per (asset, physical target) via two partial unique indexes — `(workspace_id, asset_id, dataset_id) WHERE retired_at IS NULL AND field_id IS NULL` for dataset-level bindings and `(workspace_id, asset_id, dataset_id, field_id) WHERE retired_at IS NULL AND field_id IS NOT NULL` for field-level bindings. Retirement is a `retired_at timestamptz` data fact, not a workflow enum (§4.8), so a retired binding frees its target without deleting history.
- Domain layer `internal/domain/governance/object.go`: the four typed payloads — `PhysicalBinding` (asset + dataset required, optional field refinement and transform, optional `retired_at`), `ModelGrain` (non-empty grain statement + non-empty grain field refs, optional `documented_by`), `EntityKey` (non-empty key field refs + closed `exact|deduplicated` uniqueness semantics), `JoinContract` (both dataset sides + non-empty, equal-count field refs + closed `inner|left|right|full` join-type and `one_to_one|one_to_many|many_to_one|many_to_many` cardinality vocabularies + non-empty join expression) — each with `Validate()` (full record) layered over `validateSemantic()` (structural rules before identity is minted), so invalid content is rejected with `ErrInvalidArgument` before persistence. A `GovernedObject` envelope (exactly one payload matching its type tag) plus `GovernedPatch` (JSON object content + bounded summary) complete the transport contract. No lifecycle/workflow enum exists on any of the four types; the only mutable dimension is the row version.
- Proposal targeting: `TargetPhysicalBinding` joins the T002 `TargetObjectType` vocabulary (`IsGovernedObject()` covers the four object types); `ProposalService.CreateGovernedProposal` opens drafts against them with the target enforced to the correct TypeID prefix (`ParseGovernedObjectUUID`), and `Store.SubmitProposal` validates target existence inside the submission transaction (shared `governedTargetExists` on the correct table, workspace-scoped) so a draft can never be proposed against a missing or cross-workspace target. `semantic_asset` targets remain covered by their FK.
- Application layer `internal/application/governance/object.go`: `GovernedObjectService` with `Create` (mints the typed ID per type, pins version 1, stamps the injected clock — an authoring act with no events), `Get`/`List` per type (workspace-scoped), and `ApplyGovernedChange` — the single governed mutation path, carrying the pre-minted audit event identity and the injected-clock timestamp in the command.
- Transaction discipline: `ApplyGovernedChange` runs one transaction — `SELECT … FOR UPDATE` row lock → expected-version check (`version ≠ expected` ⇒ `ErrInvariant`, the concurrency rejection) → guarded `UPDATE … SET content, version = version + 1 WHERE version = expected` (row-count re-check) → reload → exactly one audit fact → commit.
- Audit-only fact: `governance.<object_type>.applied` audit events (`semlia.governance-object/v1`, payload: objectType, objectId, new version, summary, action) are written through the shared `buildMutationPayload` builder extracted from `createMutationEvents` — but deliberately NO outbox event is enqueued (packet constraint: no new outbox event types; release publication remains the outbox signal). The choice is documented in the code and locked by an integration test asserting zero outbox rows for governed-object application.
- Refactor per packet: one shared persistence pipeline for all four types — `internal/adapters/postgres/governed_objects.go` defines a `governedObjectSpec` (per-table sqlc wiring for exists/lock/apply/get/list/create plus row mapping) and writes the create/get/list/apply orchestration once over the spec registry; `fieldRefsToJSON`/`fieldRefsFromJSON` share the physical-reference array encoding (TypeID strings), and `versionOf`/`parseGovernedObjectUUID` are single shared helpers. No four-way divergent implementations.
- `pkg/identity`: TypeID prefixes registered per ADR-0003 — `phb_` (physical binding), `mgn_` (model grain), `eky_` (entity key), `jct_` (join contract) — with the full `TypedID` kind/alias/constructor/parser set, mirroring the T002 registration pattern.
- sqlc: `db/queries/governed_objects.sql` (24 queries — create/get/list/lock-for-update/apply/exists per table) + generated `internal/adapters/postgres/sqlc/governed_objects.sql.go`; `db/sqlc.yaml` includes migration 000007 (`make db-generate` clean).
- No HTTP endpoints, no OpenAPI or sdk/typescript changes (`contracts-check` green); no M0/M1/T001/T002 schema semantics altered (migration 000007 only adds objects and extends the proposal target vocabulary CHECK, which data-model.md step 3 assigns to this migration); no TODO/FIXME left behind.

## Review Boundary

Deviations and decisions for reviewer attention:

1. **"One active binding per (asset, physical target)" without a lifecycle enum**: implemented as a nullable `retired_at timestamptz` retirement fact plus two partial unique indexes (dataset-level and field-level predicates, which also cleanly handles the nullable `field_id` without `NULLS NOT DISTINCT` or `COALESCE` index tricks). No status enum exists on any of the four objects; retirement is a data fact settable only through future governed-change payloads, not a workflow state.
2. **Field references are stored as jsonb arrays of TypeID strings** (`pfd_…`) in `grain_field_refs`, `key_field_refs`, `left_field_refs`, `right_field_refs`, decoded through `identity.ParsePhysicalFieldID` at the storage boundary. PostgreSQL cannot FK into jsonb, so dataset/field existence is enforced where the packet requires it (FKs on `asset_id`, `dataset_id`, `field_id`, both join sides, `documented_by`); deep membership of array references (field-belongs-to-dataset) is left to the T009 validation layer, which is where §8.2 validators live. Count symmetry of join refs is enforced in the domain (equal lengths); DB CHECKs pin the array type and (for entity keys) non-emptiness.
3. **`ApplyGovernedChange` mutates the flexible `content` column only**; structural columns (`grain_expression`, `key_field_refs`, join sides/type/cardinality, binding targets) are set at creation and retargeting changes will ride the proposal-application path of later packets. The version bump is not conditional on content equality: every application is a real governed change by definition of the path, and the DB trigger guarantees bump-by-exactly-one for any UPDATE.
4. **Audit-only, no outbox**: governed object application writes `governance.<type>.applied` audit facts with no outbox row, per the packet (`release publication remains the outbox signal`). The shared payload builder `buildMutationPayload` was extracted from `createMutationEvents` so both paths share one payload contract; existing `proposal.changed`/`release.published` serialized bytes are unchanged. When consumers need change events for the four objects, a later packet adds the outbox type at the same call site.
5. **`Create` added to the service beyond the Get/List/Apply minimum**: the packet names Get/List/Apply, but objects must enter the system through governed code rather than raw SQL (green criterion: "the four objects persist"). `Create` validates in the domain, mints the typed identity, pins version 1 and emits no events — mirroring the T002 draft-creation discipline ("draft creation is a local authoring act").
6. **Proposal targeting existence check lives inside the submission transaction**, not in the application service: `SubmitProposal` locks the proposal `FOR UPDATE`, then verifies the target on the correct table via the spec registry. This removes the TOCTOU window the service-level check would have and keeps `ProposalRepository`'s interface unchanged (no constructor signature churn for T003 wiring). Drafts may still reference not-yet-created objects; only submission is gated (packet wording).
7. **Event-payload subtlety fixed en route**: `SubmitProposal`/`TransitionProposal` assumed every proposal carries `asset_id` (T002 invariant for `semantic_asset` targets). Governed-object proposals legitimately have `asset_id IS NULL` (the T002 shape CHECK), so the `assetId` field is now included in audit/outbox payloads only when the proposal actually targets an asset. Existing `semantic_asset` event payloads are byte-identical.
8. **Downgrade deletes `physical_binding` proposals**: the T002 target vocabulary at version 6 already admits `model_grain`/`entity_key`/`join_contract`, so the 000007 downgrade only needs to remove `physical_binding` proposals before restoring the narrower CHECK — a minimal, documented data loss limited to rows the migration made possible; all other proposals and their change-sets survive.
9. **Existing test-expectation updates**: `tests/integration/db/database_test.go` now expects migration version 7, the four new tables in the inventory, the workspace-FK list extended by the four new aggregate roots, `Steps(6)` with one extra downgrade step in the populated-M0 suite, and `Steps(4)`/four downgrade steps in the populated-M1 suite. No assertions were weakened; a new populated-M2 lifecycle test was added.
10. **`transform` column type**: a nullable bounded `text` expression (`≤ 4096`) rather than jsonb — physical transforms are expressions (cast/exclusion/derivation statements), and the flexible structured extras belong in the shared `content` column that every governed object carries for the unified pipeline.

Residual work belongs to T009+: validation runs over the four object types (grain/fanout/join verification per §8.2), release manifest composition pinning the four object versions, retirement flows through governed changes, and outbox event types for governed-object changes if/when consumers need them.
