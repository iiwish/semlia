## Delivered

- OpenAPI additions (additive only, `x-semlia-contract-version` unchanged): new `Governance` tag with three paths — `GET/POST /api/v1/workspaces/{workspaceId}/governance/proposals` (`listGovernanceProposals`/`createGovernanceProposal`), `GET .../governance/proposals/{proposalId}` (`getGovernanceProposal`), `POST .../governance/proposals/{proposalId}/submit` (`submitGovernanceProposal`). New schemas: `GovernanceProposalId` (`prp_`), `GovernanceAgentRunId` (`agr_`), `GovernanceChangeSetItemId` (`chg_`), `GovernanceTargetObjectType` (semantic_asset + the four T008 governance objects), `GovernanceTargetObjectId` (prefix alternation `ast|phb|mgn|eky|jct`), `GovernanceProposalState` (full §7.5 vocabulary; only draft/proposed are reachable in this task), `GovernanceChangeOp`, `GovernanceChangeDigest`, `GovernanceChangeSetItem` (request, values typed `json.RawMessage` so client number literals survive byte-exact), `GovernanceChangeSetItemRecord` (response with item id + createdAt), `GovernanceProposalAgentAttribution`, `CreateGovernanceProposalRequest`, `GovernanceProposalSummary`/`GovernanceProposalDetail`/`GovernanceProposalPage`, plus `ProposalId` parameter and `Forbidden`/`UnprocessableEntity` response components. Contracts regenerated via `make contracts`; `make contracts-check` proves both generated artifacts current.
- AI structured-output gate (SSOT §8.6, ADR-0002 TDR-015 adoption condition "校验 AI structured output"): `internal/application/governance/proposal_input.v1.schema.json` — versioned `semlia.proposal-input/v1` (JSON Schema 2020-12) embedded with `go:embed` and compiled once via `github.com/santhosh-tekuri/jsonschema/v6` (already a direct `go.mod` require, previously used by the dbt adapter). The schema enforces: closed field sets (`additionalProperties: false` at every level), required target/title/changeSet/attribution, TypeID prefix coherence, `sha256:` digest shapes, per-op change-set shape (add carries only an after side, update both, remove only a before side) and base-revision presence for semantic_asset targets. Validation is side-effect free: it runs on the raw body before authorization evaluation, strict decode or any domain call, so a malformed agent payload costs zero writes anywhere — proven by the integration test asserting empty `proposals`, `proposal_changes`, `agent_runs` and `authorization_events` after the 422. Rejections answer 422 `AI_OUTPUT_INVALID` with a bounded, location-scoped violation summary (`/agentAttribution.inputHash: ...`) and no payload echo.
- No-substantive-change gate (SSOT §8.2): enforced in `AuthoringService` at create (all items validated first, then `hasSubstantiveChange`: updates are substantive only when before/after digests differ, adds/removes always, empty normalizes to nothing) and re-checked at submit against the persisted change-set before any state write. Rejections answer 422 `NO_SUBSTANTIVE_CHANGE`; the proposal never reaches proposed (integration test asserts the draft row is unchanged after a refused submit).
- Application layer `internal/application/governance/authoring.go`: `AuthoringService` composing the T002 `ProposalService` + `AgentRunService` with the T001 `Evaluator`; request structs (`CreateAuthoringProposalRequest`, `SubmitAuthoringProposalRequest`, `GetAuthoringProposalRequest`, `ListAuthoringProposalsRequest`, `ChangeSetItemInput`, `AgentAttribution`); `AttributionResult` with §8.6 authorship of record; target resolution (`VerifyProposalTarget` for semantic-asset targets, TypeID parse only for governed objects per the T002 draft contract); `ProposalTargetObjectTypeID` re-encoding stored target UUIDs to wire TypeIDs (ADR-0003 — no storage UUIDs on the wire).
- Server-side authorization on every endpoint: create/submit evaluate `asset.propose` (semantic-asset targets at asset scope so asset-scoped bindings grant, governed objects at their workspace scope — no object-level scope exists in the vocabulary), detail/list evaluate `asset.read` at workspace scope. Denials return 403 with the stable frontend reason code and are audited; allows are audited (FR-012/FR-013) — integration tests assert the exact `authorization_events` rows including `resource_type='asset'` + `resource_id` for the denied create.
- Persistence: `CreateProposalWithChanges` commits the draft and its full inline change-set in one transaction (a partial draft is unrepresentable), item IDs pre-minted before the transaction opens; `ListProposals` keyset query (workspace → `created_at DESC, id DESC`, opaque base64 cursor envelope `{kind, createdAt, id}` mirroring the M1 catalog cursor discipline); `VerifyProposalTarget` reuses the existing `GetAssetRevisionOwnership` query so a semantic-asset target with a missing/foreign base revision answers 404 before any write. `CreateProposal` gained `sqlc.narg(agent_run_id)`; all other T002 query behavior unchanged (`make db-generate-check` green).
- HTTP layer `internal/platform/http/governance.go`: shared `readBody`/`decodeStrict` (1 MiB bound, `DisallowUnknownFields`, `UseNumber`) and one `writeGovernanceError` mapper for all four handlers, mirroring `catalog.go` style; AI gate hook (`AgentPayloadHasAttribution` sniff → `ValidateAgentProposalInput` → 422 before anything else); `governanceTargetObjectID`/summary/detail mappers; digest/value fields serialize verbatim. Handler wiring via `httpapi.WithGovernance`; production `cmd/semlia` composes the same evaluator for catalog and governance. M1 handlers untouched except additive route-plumbing (a `proposal` route field, the governance match hook and method dispatch — no catalog route behavior change).

## Review Boundary

Deviations and decisions for reviewer attention:

1. **Agent-run attribution contract: pre-created run, validated** (packet offered "Start or pre-created; choose the simpler"). The create request carries `agentAttribution {agentRunId, model, configRevision, inputHash}`; the server validates the run exists in the workspace and that its persisted model/config revision/input hash match before attributing. `AgentRunService.Start` is deliberately NOT called by T003 endpoints: one agent run can produce many proposals (minting per proposal would strand dangling `running` rows and steal run-lifecycle ownership from the harness), `Start` requires the canonical input hash that only the harness knows at run start, and the packet ships no agent-run management endpoint in scope. Run creation remains an application-harness capability until a run-management surface ships (T004+).
2. **§8.6 authorship of record**: for agent-attributed creates, `createdBy` is derived server-side from the referenced run (its bound principal TypeID, else `agent-run:<id>`) and any client-claimed `createdBy` is ignored; `createdBy` is therefore optional in `CreateGovernanceProposalRequest` (required-by-app for non-attributed creates). Rationale: AI payloads must not claim a human author identity, and the audit trail anchors authorship to the §8.6 run.
3. **Stable error codes are uppercase** — `AI_OUTPUT_INVALID`, `NO_SUBSTANTIVE_CHANGE` — because the contract `ErrorCode` pattern is `^[A-Z][A-Z0-9_]{2,63}$` (the packet's lowercase examples would fail the shared schema). 422 responses reuse the M1 error envelope unchanged; `Forbidden`/`UnprocessableEntity` response components were added for the new paths only (M1 catalog paths intentionally untouched, including their pre-existing undocumented-403 gap).
4. **AI gate ordering**: decode-sniff → AI schema gate → strict decode → capability evaluation → substantive gate → domain transaction. The gate precedes authorization so a malformed agent payload produces literally zero writes (no `authorization_events` row either), per the packet's "zero domain writes" requirement; unauthorized schema-probing is out of scope at this trust boundary.
5. **No new migration**: `ListProposals` filters by workspace and orders `created_at DESC, id DESC` in SQL; at current scale the existing `proposals_workspace_state_idx` workspace prefix serves the filter and the sort is negligible. A dedicated `(workspace_id, created_at DESC, id)` index (mirroring `agent_runs_workspace_created_idx`) is deferred until volume justifies it, per the dependency/index minimalism discipline.
6. **Governed-object targets are not existence-checked at draft create** (TypeID prefix/shape only), honoring the T002 contract that drafts may reference objects that appear before submission; semantic-asset targets are verified (asset existence via base-revision ownership) because the storage FK leaves no draft latitude — the check converts the FK violation into a stable 404 before any write.
7. **Empty change-sets are rejected at create** (`changeSet` minItems 1 in the contract and the substantive gate applies to both human and agent creates), so via the HTTP surface every draft carries a substantive diff; the submit-side gate remains as defense in depth and is exercised through the application service because change-set item endpoints are out of T003 scope.
8. **`go.mod`/`go.sum` unchanged**: `github.com/santhosh-tekuri/jsonschema/v6 v6.0.2` is already a direct require (TDR-015 adoption condition was met by this task and is now exercised by the AI gate; the dependency previously served the dbt discovery adapter). The TDR-015 M2/JSON-Schema row is satisfied and evidenced here.
9. **`api/gen/go/types.gen.go` regenerated**: the generated Go artifact is the committed sibling of `api/openapi/semlia.v1.yaml` and is implied by the packet's "generated contracts and regenerated TypeScript types" acceptance; all other changed files sit inside `allowed_files`.
10. **Authorization resource coordinates**: proposal create/submit evaluate `asset.propose` at asset scope for semantic-asset targets (asset-scoped bindings grant; workspace bindings still grant through scope rules) and at workspace scope for the four governance objects (no object-level scope exists in the `ScopeType` vocabulary); detail/list evaluate `asset.read` at workspace scope, matching what the list reveals. Reason codes are the closed T001 vocabulary; no new codes were invented.

Residual work belongs to T004+ (validation orchestration, change-set item endpoints, publisher wiring for `proposal.changed`, review/release surfaces) — none of it pre-empted by this task's additive surface.
