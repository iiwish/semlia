## Key Decisions

1. **RFC 8785 规范化与请求指纹**：
   在 `internal/domain/governance/production.go` 中引入 `ComputeRequestDigest`，对包括工作区、命令类型、预期版本、输入摘要、目标声明及候选关联进行 RFC 8785 规范化哈希。相同幂等键再次调用时，若指纹不一致显式返回 409 `IDEMPOTENCY_CONFLICT`；若完全一致返回包含 `replayed=true` 的原执行结果。
2. **业务声明指纹与争用防范**：
   通过 `ComputeBusinessDigest` 计算不包含幂等键和操作员的纯业务内容摘要并记录至 `production_request_claims`，不同幂等键重复提交相同业务意图时返回 409 `ALREADY_PRODUCED`，附带原已生产的 `operationId`。
3. **权威草稿与版本不可变性**：
   新建生产操作原子初始化版本 1 与草稿资产（`current_revision_id = NULL`）和对应提案（`intent = 'create'`，`base_revision_id = NULL`）。PUT 操作仅允许针对已有操作递增生成新版本记录，历史版本记录不可变。
4. **强类型 TypeID 校验**：
   候选 ID、资产 ID、提案 ID、操作 ID 全部采用严格 UUIDv7 格式校验，防止外部或旧格式非法标识污染数据库。
