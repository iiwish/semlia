# Semlia 前端原型就绪度审计

审计日期：2026-09-01

## 结论

Semlia 当前前端原型已经足以作为后端开发的产品合同和交互基线。核心语义治理闭环、资产目录、资产详情、变更评审、发布门禁以及工作区 RBAC 均已形成可演示、可讨论、可验证的完整界面。

它已达到高质量开源项目的产品原型水准，但尚未达到可公开发布的一流开源产品水准。差距主要不在继续增加页面，而在真实后端、授权执行、持久化、并发与错误状态、自托管交付、安全证明和开发者文档。

## 关键流程健康度

1. 角色目录与权限架构：健康。系统角色、自定义角色、范围化分配、有效权限检查和稳定权限标识已经形成一致模型。
2. 权限解释与系统角色继承：健康。每个权限点都有简短说明，系统角色不可直接修改，并提供基于系统角色创建自定义角色的路径。
3. 知识资产发现：健康。搜索、筛选、类型、语义域、关系、绑定、就绪度和发布状态适合高密度桌面工作。
4. 语义资产理解：健康。定义、revision、生产状态、可信度、实现、关系和消费影响具备清晰的信息层级。
5. 变更评审与发布门禁：健康。版本差异、验证、审批和影响对象构成了明确的治理闭环。

## 进入后端前的决策

- 冻结当前前端原型为第一版产品合同，停止无边界视觉打磨。
- 正式接受访问控制 T001-T005 与基础里程碑 M0/T008，清除治理状态上的未决项。
- 后端第一条纵向链路优先实现身份、工作区、Casbin RBAC、审计和拒绝优先的服务端授权。
- 随后实现来源导入、语义资产、revision、搜索与详情的真实数据闭环，再接入提案、验证、评审、发布和回滚。
- ABAC/CEL 保留扩展点，不作为首个公开版本的阻塞项。

## 发布前仍需补齐

- 真实登录、会话、OIDC/SSO、令牌过期与撤销。
- 服务端强制鉴权、最小权限、最后管理员保护、职责分离和不可变审计。
- 数据库迁移、并发冲突、乐观锁、加载/空/错误/重试状态。
- 大数据量分页、搜索性能、代码分包和生产性能预算。
- Docker Compose、自托管示例、API/MCP/CLI 文档、升级与回滚文档。
- 依赖与镜像扫描、SBOM、签名、发布流程、贡献与安全响应机制。
- 中英文关键路径一致性及完整无障碍审计。
