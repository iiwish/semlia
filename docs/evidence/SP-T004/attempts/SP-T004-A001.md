# SP-T004-A001 Worker Handoff

## Result

SP-T004（组合语义生产：验证审核、原子发布与受保护回滚）实现已全部完成并通过完整验证矩阵。本任务实现了：
1. **多对象操作原子提交**：`SubmitOperation` 冻结操作版本，触发 Attempt 1 确定性验证任务。
2. **确定性验证与 CAS 重验**：`ValidateOperation` 支持 CAS 自增验证轮次（Attempt 2+），计算确定性 `ValidationDigest`。
3. **SoD 职责分离审核**：`ReviewOperation` 绑定 active attempt 与 setDigest，禁止创作者自审（403 `SOD_CONFLICT`），批准保持 `in_review`，拒绝转移至 `rejected`。
4. **单事务原子发布**：`PublishOperation` 校验 Head（CAS）、验证与审核状态，在单一数据库事务内完成：生成新资产 revision、更新语义资产状态、写入 release 表及其保护扩展（`rollback_depth=0`, `root_release_id=self`）、写入 release_proposals、写入 manifest 与 before pins、更新 catalog 投影与生成 outbox/audit 事件。
5. **受保护回滚**：`RollbackOperation` 仅限 latest release，校验 expectedHead，自增 `rollback_depth`，继承 `root_release_id` 并链接 `rollback_parent_id`，将 absent before pins 对应的语义资产安全恢复为草稿状态（清空 current_revision_id，剔除出新 release manifest），生成归因角色 `role='reverted'`。
6. **旧单项接口旁路拦截**：在旧 Proposal Submit、Proposal Review、Release Publish、Release Rollback 接口中全面拦截生产集合成员与受保护发布，返回 HTTP 409 `PRODUCTION_SET_REQUIRED`。

## Key Decisions & Bug Fixes

1. **proposals 状态机转移严格遵循触发器约束**：
   - 触发器限制跃迁路径：`('draft', 'proposed') -> ('proposed', 'validating') -> ('validating', 'in_review') -> ('in_review', 'released')`。
   - `SubmitOperationTx`、`ReviewOperationTx` 和 `PublishOperationTx` 严格依序更新提案状态，并在 review 阶段保证 `decided_at IS NULL`，仅在最终 release/reject 时写入 `decided_at`。
2. **Publish / Rollback 幂等重放 TypeID 还原**：
   - `production_commands` 表中以 UUID 存储 `result_id`，`GetProductionCommand` 依据 `result_kind` 还原为 `rls_` 或 `prodop_` 前缀的 TypeID，确保重放时 `ParseReleaseID` 精确识别并立即返回 `replayed=true`。
3. **原子发布单事务生成 Asset Revision**：
   - `PublishOperationTx` 在向 `release_assets` 写入前，在同一事务中为每个发布资产创建 `asset_revisions`（计算 sequence 与 content digest），并将 `semantic_assets` 的 `current_revision_id` 与 `lifecycle_state='active'` 原子同步。
4. **受保护回滚精确撤销 Absent 目标**：
   - `RollbackOperationTx` 遍历 `beforePins`，对发布前本为 `absent` 的新资产，将其从回滚的新 release 清单中剔除，并在 `semantic_assets` 中重置为 `current_revision_id=NULL` 与 `lifecycle_state='draft'`。
5. **OpenAPI 响应 Slice 规范化**：
   - 响应中的 `afterAssets`、`afterObjects`、`beforePins`、`reviewIds` 等列表统一使用 `make([]T, 0)` 初始化，保证 JSON 序列化始终输出 `[]` 而非 `null`。
