# 实际模型质量

实际调用 4/30，均为配置的 `deepseek-v4-flash`，不是协议替身。第一次覆盖三个语义对象，第二次扩展至十对象集合，第三及第四次完成原始建议、人工纠正、未确认拒绝、业务声明、重验、职责分离审核、发布与 Git 内容投影；第四次额外核对服务器回读及已发布业务内容。四次返回成功，无结果不明重试；时长分别 18.745s、35.232s、36.187s、42.001s。供应商实际费用没有权威回执，记录为 null，不以门禁保守上界冒充实付金额。

最终样例使用两实体、一收入口径、三绑定、两键、一粒度及一 Join。输入包含用户可预选的结构化骨架和真实发现的固定物理引用；本测试证明建议、保留引用及纠正路径，不声称模型从空白自主发现所有业务关系。黄金答案独立保存，未进入初始模型输入。

固定八项比较：最终原始结果 6/8，人工纠正 8/8，详见 [机器可复核评分](model-quality.json) 与 [评分程序](score-model.mjs)。原始结果完整保留对象身份和物理引用，但收入定义仍是泛化的订单金额描述，转换表达式为 `amount`，不满足“仅已支付且排除取消”的样例业务答案。纠正既修改定义/范围，也将执行转换改为 `CASE WHEN status = 'paid' THEN amount ELSE 0 END`，不是只改展示文字。

未决表达并不稳定：第一轮为 null，十对象三轮给出了泛化的非空定义，第四轮的 scope 仍为 null。该内容仍是未确认建议，不能作为业务事实；真实服务端验证在缺确认时记录 `PRODUCTION_BUSINESS_RULE_UNCONFIRMED`，确认并重新验证后才接受独立审核和发布。此限制保留为模型质量风险，不将 8/8 人工纠正分数宣传为模型成绩。评分使用服务器回读的版本 2 声明，并额外检查已发布目录定义和绑定转换，不只比较客户端请求。

“人工”在此指测试中的合成人类身份与固定答案应用，不是现实业务所有人的签字，也不是模型自评。产品阶段仍须用户验收，不支持无人审核自动发布的结论。
