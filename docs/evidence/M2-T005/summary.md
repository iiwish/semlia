## Delivered

- Closed DecisionInputs schema extended (`internal/domain/governance/policy.go`): the T002 inputs gain `targetObjectType`, the four §8.3 diff categories (`affectsDefinition`, `affectsRelations` joining the existing computation/access/contract flags), the T004 validation outcomes (`validationRunCount`, `validationFailedCount`, `blockerCount`, `warningCount`, `infoCount`), `evidenceLinkCount`, the tri-state `ownerAssigned` (`assigned|unassigned|not_applicable`) and `authorKind` (`human|agent`). The not-yet-computable §8.3 categories (`consumerCount`, `historicalAcceptRate`) are explicit nullable placeholders (JSON `null` until M4), so M4 populates values under a new rule version without a schema-shape change that would break stored digests. `Validate()` enforces the closed enums and non-negative counts; the zero value of the new vocabularies stays legal so inputs persisted before T005 still parse and re-evaluate (recomputability, SSOT §8.2). Unknown fields remain rejected.
- Versioned rule-table engine (`internal/domain/governance/policyrule.go`, decision D3 — no cel-go/DSL): `PolicyRule` rows (`id`, `rule_version`, `priority`, `match`, outcome `risk_level|routing|reason_code|explanation`) are evaluated by `EvaluatePolicyRules` in priority order (higher number first, ties by rule id; first match wins). Match conditions are a closed expression form — `{"field","op","value"}` leaves with `eq|ne|gt|gte|lt|lte|in|notIn`, `all`/`any` groups, and `{}` match-all — strictly decoded against the DecisionInputs field names derived from the schema itself, so a stored rule cannot reference an unknown field or smuggle an open expression language. No match fails safe to the expert channel with the stable `RISK_POLICY_UNMATCHED` reason and the `semlia.risk.v1/default` matched policy (§8.2 degradation). `PolicyRule.Validate` rejects any routing outside `expert|batch`, making the deferred auto lane unexpressible at the evaluator level as well as at both database CHECK constraints. `EvaluateRiskRule(version, inputs)` (the T002 entry point) is now implemented over `CanonicalPolicyRules(version)` — the canonical 1.0 table — and reproduces the exact T002-locked outcomes for every input.
- Policy rule vocabulary (`migrations/000008_m2_policy_rules`, seeded-function style of 000005): `policy_rules` is keyed `(rule_version, rule_id)`, ordered by `priority DESC, rule_id`, carries the immutable-row trigger, and is seeded idempotently via `seed_m2_policy_rules()` with six rows mirroring `governance.CanonicalPolicyRules("1.0")`: `blockers` (100, `blockerCount>0` → high/expert/`RISK_BLOCKER`), `production-computation` (90, computation ∧ production → high/expert/`RISK_PRODUCTION_COMPUTATION`), `access-or-contract` (80, access ∨ contract → high/expert/`RISK_ACCESS_OR_CONTRACT_CHANGE`), `computation` (70, → medium/expert/`RISK_COMPUTATION_CHANGE`), `production-change` (60, → medium/expert/`RISK_PRODUCTION_CHANGE`), and the `low-risk` catch-all (10, → low/batch/`RISK_LOW_BATCH`). `outcome_routing` is CHECK-constrained to `('expert','batch')` — inserting `'auto'` violates the constraint (locked by test); `database_test.go` expectations moved to version 8.
- Deterministic inputs collectors (`internal/application/governance/decisioninputs.go`): `ClassifyDiffCategories` maps each change-set field path onto the closed category set by lowercased first dot-segment prefix (documented prefix table; unclassified prefixes count as definition/docs so routine metadata such as owner edits never fakes a computation change). `BuildDecisionInputs` is a pure function of persisted state: proposal coordinates, classified change-set, validation outcome summary, and per-target facts. Per-target collectors are registered in `InputsCollectorRegistry` — the semantic-asset collector reads the base revision owner content, one asset-scoped collector serves the three asset-anchored governance objects (object → asset → facts/current-revision owner), and the join-contract collector returns the explicit not-applicable facts — so a new object type adds a collector registration, never a trigger conditional. Identical persisted state yields byte-identical inputs and inputs_digest (locked at unit and cross-workspace integration level).
- Decision trigger (`internal/application/governance/decision.go`, `policy.go`, `validatejob.go`): `PolicyService` gained `WithRuleSource` (decisions evaluate the DB-loaded rule rows when wired; the canonical built-in table otherwise) and `EnsureDecision` — the one decision per `(proposal_id, rule_version, inputs_digest)`, computed through the T002 `Decide` persistence path with `LinkProposal`. `PolicyDecisionTrigger.EnsureDecisionForProposal` runs the §8.2 decision step only for in_review proposals: proposal + frozen change-set + validation summary + per-target facts → closed inputs → rule table → exactly one `policy_decisions` row. `ValidationExecutor.transitionToReview` ensures the decision immediately after the validating→in_review transition (both the clean and the degraded-completion paths), and `Execute` re-ensures it when a crashed attempt retries a proposal already in in_review. `CreatePolicyDecision` is now conflict-safe: the `UNIQUE (proposal_id, rule_version, inputs_digest)` index collapses duplicates into the stored row, making idempotency a database guarantee. A materially changed state (new digest under the same rule version) legitimately appends a new row and re-links the proposal; past rows stay immutable (append-only trigger, locked by test).
- Read surface (`api/openapi/semlia.v1.yaml` additive, contracts regenerated): `GET /api/v1/workspaces/{workspaceId}/governance/proposals/{proposalId}/policy-decision` (`getGovernancePolicyDecision`) returns the latest decision (ruleVersion, inputsDigest, riskLevel, routing, matchedRuleId, reasonCode, explanation, matchedInputFields, createdAt) ordered `decided_at DESC, id DESC` over the existing `policy_decisions_proposal_idx`; 404 before validation completes or for unknown proposals; workspace-scoped `asset.read` authorization; no storage UUIDs on the wire. `GovernanceRoutingChannel` is the wire vocabulary `expert|batch` only; no numeric score field exists anywhere in the contract.
- Worker wiring (`cmd/semlia/main.go`): the production worker registers the validation handler with a rule-source-backed `PolicyService`, so every validation completion in production computes its decision from the seeded rule rows. Explainability is resolved at read time from the immutable rule rows (explanation plus the matched rule's condition fields — the input categories that drove the decision).

## Review Boundary

Deviations and decisions for reviewer attention:

1. **`EvaluateRiskRule` is reimplemented over the canonical rule table** (same signature, identical outcomes). The T002 hardcoded switch became the `semlia.risk.v1` table so the rule rows are the single decision mechanism; T002's tests were neither edited nor weakened and pass unchanged, and the T005 parity test locks the table to the entry point over an input corpus.
2. **The rule table exists twice by design**: `CanonicalPolicyRules` (Go, seed source of truth and pure evaluation for T002's API) and the `policy_rules` rows migration 000008 seeds. This mirrors the 000005 seeded-vocabulary pattern (which mirrors `web/src/data.ts`); `TestSeededPolicyRulesMatchCanonicalTableAndReproduceDecisions` locks row-by-row equality and decision equality of the DB-loaded table against the domain entry point.
3. **Decisions evaluate the DB rows, not the Go table, in production**: the worker wires `PolicyService` with a store-backed rule source. If the table is unevaluable at runtime (malformed rows cannot exist because `policy_rules` is immutable and validator-locked, but defense in depth), the decision degrades to the fail-safe expert outcome (`semlia.risk.v1/default` / `RISK_POLICY_UNMATCHED`) instead of failing the pipeline — §8.2 "degrade to human handling, never silently pass". A DB-level rule-load error still fails the job so the lease/retry/degrade path applies.
4. **The crash-recovery window is closed by re-ensuring the decision**: `Execute` previously returned early for a proposal already in in_review (T004 behavior for "left validating"); it now runs the idempotent decision step on that path so a crash between the transition and the decision cannot strand an in_review proposal without one. T004's assertions are unchanged — the rejected-proposal test still sees zero runs and no transition, and rejected proposals never gain decisions.
5. **`CreatePolicyDecision` is conflict-safe**: `ON CONFLICT (proposal_id, rule_version, inputs_digest) DO NOTHING` plus a read-back returns the stored row instead of a 23505 error, making the one-row-per-(proposal, version, digest) guarantee a database property rather than an application check. On conflict the proposal link is left exactly as the original creation recorded it.
6. **Materially changed state appends a new row (documented rule)**: if validation re-runs and the inputs digest changes under the same rule version (e.g. evidence links added to the target), a new append-only decision row is persisted and the proposal is re-linked; the read surface returns the latest by `decided_at DESC, id DESC`. Past rows are never mutated (immutable trigger, locked by test).
7. **Unclassified field-path prefixes classify as definition/docs** in `ClassifyDiffCategories`: the closed prefix table only lifts explicitly risk-bearing fields (computation/relations/access/contract) into routing inputs, so §8.4's batch-channel examples (owner additions, documentation) are never mis-routed by prefix typos; the fail-safe rule-table default covers everything else.
8. **M2 approximations are explicit in the closed schema**: `productionEnvironment` is deterministically `false` (no environment dimension is persisted in M2) but stays rule-addressable; evidence completeness is `evidenceLinkCount > 0`; join contracts are assetless so asset type, evidence and owner are `not_applicable` rather than fabricated.
9. **The not-yet-computable §8.3 categories are nullable placeholders, not "not_applicable" strings**: `consumerCount`/`historicalAcceptRate` marshal as JSON `null` today so M4 can populate real values without a field-type change that would make stored inputs unparseable and break digest recomputability.
10. **A decision whose inputs cannot be computed fails honestly**: for a proposal whose governed target is absent (impossible through the submission gates, exercised by synthetic worker-seed rows), the decision step errors, the degrade path still lands the proposal in in_review, and the job dead-letters with human handling instead of persisting fabricated inputs.
11. **`api/gen/go/types.gen.go` regenerated**: the committed generated Go artifact is the sibling of `api/openapi/semlia.v1.yaml` and is implied by the packet's regenerated-contracts acceptance (same reasoning as T004 deviation 8); `sdk/typescript/src/schema.gen.ts` sits inside `sdk/typescript/**`. All other changed files sit inside `allowed_files`.
12. **The read response additionally carries `matchedInputFields`** beyond the packet's field list: MUST DO 5 requires the input categories that drove the decision, resolved from the matched rule's closed conditions (a match-all rule names none — it routed through the absence of every category).

Residual work belongs to T006/T007 (review confirmation, release and rollback surfaces — none pre-empted here) and to M4 (populating `consumerCount`/`historicalAcceptRate` under a new rule version, G2/G3 shadow evaluation — the auto lane remains unexpressible in this vocabulary by construction).
