# 候选版本阻断修复

日期：2026-09-14。状态：本地修复与验收通过，远程新候选版本验收待执行。范围为 rc.1 发布流水线的浏览器失败及源码门禁超时；不部署、不修改 rc.1 tag。

## 根因与修复

生产事务取得工作区行锁后，通过使用全局连接池的 Store 读取权限快照。其他生产请求占用连接并等待同一行锁时，持锁事务也可能等待空闲连接，形成连接池与数据库锁之间的循环等待。高核数本机的默认连接池掩盖了问题。

- 默认本机连接池的旧版本浏览器验收 12/12 通过。
- 将隔离验收服务连接池固定为 4 后，旧版本复现与远程相同的三个失败：切换审核者后对象名称缺失、生产列表 API 超时、刷新草稿后资产地址缺失，9 通过、3 失败。
- 新增单连接集成回归，修复前无法越过权限快照读取，未到达预期的输入完整性检查。
- 生产权限快照使用当前事务绑定的 queries，不再借用第二个连接；覆盖输入、动作、规则确认、生成、发布清单读取及 supersede。supersede 的原版本读取同样复用当前事务；独立读取保留原来的 repeatable-read 事务边界。
- 初版权限修复后的 4 连接验收仍为 10 通过、2 失败。现场 `pg_stat_activity` 捕获生成读取事务持工作区锁、另外三个连接等待同一锁；生成路径内部的生产版本读取也借用了第二个连接。生成版本、工作区 agent 与回滚命令读取均绑定当前事务。
- 正常草稿的单连接生成历史回归在补齐修复前以 `context deadline exceeded` 失败；修复后输入权限、草稿读取/动作/规则/生成历史、生成排队及结果读取三个单连接集成测试全部通过（18.460 秒）。
- 隔离浏览器验收固定 4 个连接，保持原有浏览器断言、20 秒等待及零重试，不放宽业务规则或伪造身份。

源码门禁的远程记录明确为超过 10 分钟上限，非断言失败。CI 配置限制 Go 包并行为 1、Vitest workers 为 2，job 上限为 30 分钟；保留全部检查项。
