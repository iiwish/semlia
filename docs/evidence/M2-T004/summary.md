## Delivered

- Validator registry (`internal/application/governance/validator.go`): application-layer `Registry` with stable, ordered ids `schema`, `reference`, `structural`, each at fixed version `1.0.0`; `Get` refuses unknown ids (never silently accepted by the run-recording path), `IDs`/`All` report the stable entries, and `NewRegistry` makes future validators a registry entry only. Severity vocabulary reuses the T002 §3.3 enum (`blocker|warning|info|not_applicable`; only `blocker` blocks release candidacy). `ValidationInputDigest` hashes the canonical JSON of the run inputs — validator id/version, proposal snapshot, target snapshot and the change-set projected onto its semantic fields (no ids, no timestamps, no volatile bookkeeping) — as a repository-wide `sha256:` digest, so identical logical inputs always reproduce the identical digest (SSOT NFR-003).
- v1 validators (`internal/application/governance/validators.go`), each a deterministic pure function over `(proposal snapshot, target snapshot) → findings []{severity, code, message, details, input_digest}`: `schema@1` re-checks op/value/digest pairing per item (`SCHEMA_ITEM_SHAPE`), field-path bounds (`SCHEMA_FIELD_PATH`), semantic-asset target identity (`SCHEMA_TARGET_IDENTITY`) and required-field removals per target type (`SCHEMA_REQUIRED_FIELD_REMOVED` — `name`/`definition` for semantic assets, the structural columns of the four T008 governance objects). `reference@1` fails closed on a missing target asset/base revision or governed target (`REFERENCE_TARGET_MISSING`), resolves every whole-string TypeID token extracted from change-set values against the workspace (`REFERENCE_UNRESOLVED` blocker), and distinguishes malformed tokens (`REFERENCE_MALFORMED` blocker) from prefixes without a workspace resolver (`REFERENCE_UNSUPPORTED_KIND` warning). `structural@1` verifies every provided digest equals the sha256 of its canonical value (`STRUCTURAL_DIGEST_MISMATCH` blocker) and signals no-op updates (`STRUCTURAL_NO_OP` warning, §8.2 no-op detection). Token extraction walks JSON values deterministically (sorted object keys); values embedded inside larger strings never match.
- Orchestration (`internal/application/governance/orchestration.go`): `ValidationOrchestrator.BeginValidation` implements the §8.2 hand-off — after the T003 submit transition to proposed it transitions proposed→validating through the T002 `ProposalService.Transition` state machine and enqueues exactly one job of type `governance.proposal.validate` on the M0 jobs framework (max attempts 3, idempotency key `governance.proposal.validate:<proposal-uuid>:<attempt>`; the jobs-table unique index collapses concurrent enqueues into exactly one row). The payload carries the proposal TypeID, never the storage UUID. `BeginValidation` is idempotent: the validating transition is a legal no-op when a crashed submit already applied it.
- Validator-execution loop and job handler (`internal/application/governance/validatejob.go`): `ValidationExecutor.Execute` is the extracted loop (packet refactor step) — it loads the proposal, skips silently only when the proposal is gone or no longer validating (e.g. rejected concurrently: complete, no transition, no error loop), builds the deterministic snapshot, then runs every registry validator in stable order. Per validator it reuses the run row from a crashed attempt (the `validation_runs` unique index allows exactly one run per proposal per validator version), records only findings not already persisted (deterministic finding keys make retries duplicate-free), always appends the run-completion record carrying the run input digest, and finishes the run `succeeded` for a clean pass or `failed` when any blocker finding blocks release candidacy (§3.3 via the T002 `FinishRun` gate). `ValidationJobHandler.Handle` adapts the loop to the jobs framework: infra errors return as handler errors so the worker lease/backoff retries them; on the final attempt the handler first degrades — one failed run under the stable `orchestration` id with a single bounded `VALIDATION_INFRA_FAILURE` finding (raw infra error text never persisted) — and then still transitions validating→in_review. Blocker outcomes and infra failures therefore both end with the proposal in in_review and the failure outcome persisted: never silent pass, never auto-rejection, no auto-publish.
- Submit hook (`internal/application/governance/authoring.go`): `AuthoringService.SubmitProposal` walks draft→proposed (T003 gates unchanged: authorization, change-set re-check, no-substantive-change) and then invokes the orchestrator wired via `WithValidationOrchestrator` (submit fails closed without it). A crashed submit resumes: re-submitting a proposal already in proposed/validating re-runs orchestration instead of erroring, so a client retry cannot strand a proposal between states; decided states answer 409. New read method `ListValidationRuns` returns each run with its results ordered by run start, workspace-`asset.read` authorized and 404 for unknown proposals.
- Persistence (`db/queries/governance.sql`, `internal/adapters/postgres/validation_refs.go`, sqlc-regenerated): `GetProposalValidationRun` (idempotent reuse against the unique index), `ListProposalValidationRuns` (read surface ordering), `SemanticAssetExists`/`AssetRevisionExists`/`PhysicalDatasetExists`/`PhysicalFieldExists` and `ValidationGovernedObjectExists` (reusing the T008 spec table) behind `ResolveValidationReference`, which maps an `ast_|rev_|pds_|pfd_|phb_|mgn_|eky_|jct_` token to a workspace-scoped existence verdict and explicit `malformed`/`unsupported` verdicts otherwise. No migration was needed — T002 already owns the validation tables.
- Read surface (`api/openapi/semlia.v1.yaml`, additive; contracts regenerated): `GET /api/v1/workspaces/{workspaceId}/governance/proposals/{proposalId}/validation-runs` (`listGovernanceValidationRuns`) returning `GovernanceValidationRunPage` of `GovernanceValidationRun` (`val_` id, `prp_` proposal, validatorId, validatorVersion, status, startedAt/finishedAt, results) with nested `GovernanceValidationResult` (`vlr_` id, §3.3 severity, stable uppercase code, message, `inputDigest`, details, createdAt). No review/release/rollback endpoints, no transitions beyond validating→in_review, `x-semlia-contract-version` unchanged, no storage UUIDs on the wire.
- Worker wiring: production `cmd/semlia` registers the handler on the existing worker loop (`worker.Register(ValidationJobType, ...)`) with lease/retry semantics and wires the orchestrator into the server-side authoring service; the test harness (`tests/integration/worker/validation_test.go`) drives the same production handler against real PostgreSQL under the real `Worker.RunOne` claim/retry/dead-letter loop, without the Compose stack.
- Tests: registry/validator unit suite (stable ids/versions, unknown-id refusal, pure-function determinism, digest stability, per-validator finding matrices), full-stack HTTP journey (clean run: exactly one queued job with the pinned idempotency key, worker execution, 3 succeeded runs with digests, in_review, no blocker results, no UUID leak), blocker degradation with cross-workspace determinism proof (identical change-set inputs in two workspaces produce identical findings; run `failed`, proposal in_review), read-surface 404, infra retry-then-degrade and rejected-proposal no-error-loop.

## Review Boundary

Deviations and decisions for reviewer attention:

1. **Run-level input digest is recorded on results, not on the run row** (no new migration). `validation_runs` has no digest column (T002 schema), so every run persists exactly one deterministic `*_COMPLETED` info result (`SCHEMA_COMPLETED`/`REFERENCE_COMPLETED`/`STRUCTURAL_COMPLETED`, details `{findingCount}`) carrying the run input digest, in addition to per-finding digests. This satisfies NFR-003 (runs record tool version, input hash and results) within the packet's "prefer NO new migration" constraint; the read surface exposes `inputDigest` per result.
2. **Infra degradation records a run under validator id `orchestration` @ `1.0.0`.** The unique index forbids re-using a per-validator run row for the harness failure, and validators that never ran must not fabricate runs. The degradation run carries exactly one `VALIDATION_INFRA_FAILURE` info finding with a deterministic digest (`{proposalId, reason}`); the raw infra error text never reaches persistence (locked by the no-leak assertion). Severity is `info` — the failed run status carries the human-handling signal without polluting the T002 blocker/release-candidacy gate.
3. **The final job attempt degrades, then returns the infra error, so the job row dead-letters.** A green job row for a failed validation would read as a silent pass at the ops layer; the degradation writes persist before the error return, so the proposal never stays stuck in validating while the job honestly lands in the dead-letter retention class.
4. **Submit response state is now `validating` (was `proposed`).** The packet requires the proposed→validating transition and the enqueue inside the submit command, so the T003 journey assertions were updated to the new intermediate state. This is the packet-required behavior change, not a weakened assertion: the submit endpoint additionally proves exactly one enqueued job and the in_review completion in the same suite.
5. **Crash-recovery resubmit**: `SubmitProposal` on a proposal already in proposed/validating resumes orchestration (idempotent transition + idempotent enqueue) instead of failing, so a client retry after a crashed submit cannot strand a proposal between states; decided states answer 409. The validating→validating no-op transition records one extra `governance.proposal.state_changed` audit fact and `proposal.changed` outbox event, but only on that recovery path; no new outbox event type exists.
6. **`reference@1` warns (does not block) on registered prefixes without a workspace resolver** (`REFERENCE_UNSUPPORTED_KIND`): evidence, principal or other future ids embedded in values degrade to human handling instead of hard-failing a valid proposal; supported kinds (assets, revisions, datasets, fields, the four governed objects) that do not resolve are blockers.
7. **`schema@1` required-field scope**: removal of `name`/`definition` (semantic asset) and the structural columns of the four T008 governance types is a blocker; full AssetTypeProfile-driven required-field validation (per-type content templates, §3.3 profiles) belongs to T005 and was not pre-empted.
8. **`api/gen/go/types.gen.go` regenerated**: the committed generated Go artifact is the sibling of `api/openapi/semlia.v1.yaml` and is implied by the packet's regenerated-contracts acceptance (same reasoning as T003 deviation 9); `sdk/typescript/src/schema.gen.ts` sits inside `sdk/typescript/**`. All other changed files sit inside `allowed_files`.
9. **No dedicated index for the read surface**: `ListProposalValidationRuns` orders by `started_at, validator_id` over the existing `validation_runs_proposal_validator_idx` prefix; a proposal holds at most one run per validator version, so volume does not justify a new index (dependency/index minimalism).
10. **Worker-test failure injection** goes through a repository wrapper that fails `ListProposalChanges` for a configured number of calls, proving the real worker loop's retry/backoff/dead-letter behavior around the production handler without mocking the jobs framework.

Residual work belongs to T005+ (policy/risk routing over recorded findings, review and release surfaces, publisher wiring for `proposal.changed`) — none of it pre-empted by this task's additive surface.
