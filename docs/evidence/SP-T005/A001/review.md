# T005 风险复核

状态：Needs_Review。规格、安全及 QA 由同一执行者按顺序自检；无独立子代理评审。

## 规格符合性

生成输出使用批准的完整目标结构 schema，并结合领域内容、身份、局部引用、固定来源和当前权限检查。有效的新绑定、粒度、键和 Join 建议经明确人工应用才成为提案；原始建议与人工差异分开保存。成功原文、关联、AgentRun/Step 和最终状态在同一事务提交。

服务端 grant 默认空。费用上限来自操作员配置的保守计费边界，不从客户端数字推断授权，不把未知实际费用记为 0。模型配置修订覆盖 setting/provider；读取的修订本身不授权调用。

## 工程风险

- 并发同 key 只有一个 run；不同请求复用 key 拒绝。恢复只查询原运行，不重新付费调用。
- 排队前与调用期间撤销发起人、Agent 或模型配置均拒绝；来源推进、来源读取权限撤销及草稿替换均有真实失败断言。
- 模型请求在事务外。持久化领取后遇到提交故障或工作租约回收，以 outcome_unknown 收敛；迟到结果不能覆盖终态。
- 排队、输出和人工应用的 deferred commit 故障验证事务回滚；成功原文无部分落库，人工版本无部分更新。
- HTTP 拒绝伪造主体、工作区、运行模式、费用归因和批准字段；输出拒绝伪造目标身份。机器凭据 allowlist 不扩张。
- 人工应用复核成功 run、同操作、精确输入版本和 digest，读时重算原输出、应用内容和完整 delta；generation 发起人与 Agent 保留为集合贡献者。
- 未决内容保留为合法草稿，但共享验证器产生独立 definition/scope blocker。失败 findings 使用与数据库一致的空对象 Details，完整性防线没有被绕过。

## QA 与残余边界

全量治理集成、生成 race 检查、HTTP/配置/readiness、PostgreSQL 18 迁移生命周期、API/SQL 生成物及仓库检查通过，日志见交付报告。合成成功夹具明确提供业务范围；未决回归保留 null，不能通过改夹具删除失败覆盖。

本任务没有执行 PostgreSQL 17 矩阵、完整 `make check`、性能压测、浏览器或真实模型验收。协议替身只证明结构和治理控制，不证明模型会正确理解所有提示注入或生成业务规则；实际模型质量属于 T007。操作员必须核实计费上界适用于所配置供应商。

数据库持续不可用时不能保证立即记录最终失败；恢复后以已保存的领取状态防止重复调用。没有将存储中断伪装成成功，也不以自动再次调用模型弥补缺失结果。
