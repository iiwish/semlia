# 合成零售数据

版本 `retail-v1`，默认种子 `20260914`。300 名合成客户、30 个商品、3000 笔订单及对应明细与退款，交易区间为 2026-04-01 至 2026-06-29。姓名和业务事实均为生成内容。

## 业务规则

- 币种为 CNY，金额字段使用整数分，展示人民币元需除以 100。
- 订单金额等于明细数量乘单价之和；pending/cancelled 订单不计入支付金额或支付订单数。
- 支付金额为 paid 订单金额总和，支付订单数为 paid 订单计数。
- 净收入为 paid 订单金额减去这些订单的 succeeded 退款金额；pending 退款不扣除。
- 本案例按订单日期归属固定交易期间，并在数据截止日核对退款，不将其解释为真实会计收入确认标准。
- 订单到客户为多对一；订单到明细、退款为一对多。先在订单粒度汇总退款，再核对净额，禁止直接联接明细和退款造成金额倍增。

## 演示边界

生成的数据与独立汇总用于校验合成业务自洽。语义定义和业务确认是合成案例的人工声明，不代表真实企业签署或 AI 生成。Semlia 使用正常接口发现 SQL 工件并生产语义；本包不声称支持任意 SQL 或复杂退款查询执行。

运行生成器测试：`node --test examples/resume-demo/generate.test.mjs`。环境初始化器负责将数据写入归属明确的专属位置；模块导入不会写文件或连接数据库。
